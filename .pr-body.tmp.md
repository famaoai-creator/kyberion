## Summary

Consolidate "which operation needs which authority" into a single declarative authorization registry (P0+P1 plus the 3-layer extension path of `docs/UNIFIED_AUTHORIZATION_POLICY_DESIGN.ja.md`):

- **`libs/core/foundation/authorization-registry.ts`** — new foundation leaf: closed `EffectClass` taxonomy (7 classes), `AuthorityRequirement` union, exact + longest-prefix lookup, fail-safe undeclared default, `source` provenance (`code | overlay | plugin:<id>`), delegation attributes folded in. 22 exact declarations + 3 prefix families cover every operationId routed through external admission.
- **`libs/core/governance/authorization-overlay.ts`** — Layer 1: governed JSON overlay via `defineCatalog` (schema-validated, signature-cached, `fallbackOnInvalid`, customer override supported) plus an inbound-only plugin loader hook.
- **`libs/core/plugin/plugin-authorization-overlay.ts`** — Layer 2: managed-plugin manifest `authorizations` blocks, gated on `isManagedPluginActivationAllowed`, digest-cached (activation-aware), errors never cached.
- **Merge rules**: code declarations always win (data can add coverage but never weaken, including via longer shadow prefixes); schema forbids `local_only`/`free` in all data layers; collisions dropped with a warn.
- **Boundary gate** (`authorization-registry.test.ts`): scans `libs/core`/`scripts`; every operationId at admission call sites must be code-declared with an `external_*` effect class; delegation parity enforced both directions.
- **Rewiring**: `isDelegableExternalOperation` derives from the registry; `admitExternalOperation` warn-logs undeclared operationIds (P0 measurement, no behavior change).
