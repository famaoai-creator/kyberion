# エージェント・推論経路の選択設定

ミッションの担当者と、推論を実行するランタイムは別の設定です。

- ミッション詳細の選択欄: チームロールごとのエージェント識別子、必要に応じてプロバイダーとモデル。
- 推論画面の選択欄: 推論ロールごとのランタイム、プロファイル、プロバイダーとモデル。

## 選択方式

| 方式 | 動作                                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------------------- |
| 自動 | 既存のポリシーと候補の評価で選ぶ                                                                                     |
| 優先 | 指定した利用可能・適格な候補を優先し、代替した場合は理由を表示する                                                   |
| 固定 | 明示した対象を維持する。利用不能、不正なモデル、権限・スコープ・必要能力・独立レビュー条件との不整合があれば停止する |

エージェント識別子を固定することは、新しい権限の付与ではありません。
モデルを明示して固定した場合、別のモデルへの自動置き換えは行いません。
設定のない既存のミッションと推論ロールは従来の解決規則を維持します。
既存の provider strategy の strict と、新しい固定設定は別の契約です。

## 確認・変更

1. 対象ミッション、または推論画面を開き、現在の設定・解決された選択・選択元・理由を確認します。
2. 必要なスコープを持つ認証済み管理者として「編集」を選びます。
3. 方式と対象を指定して「プレビュー」を選びます。プレビューは設定を保存せず、キャッシュ済みの準備状況を使います。モデル呼び出しや接続確認は実行しません。
4. 結果と、上位ポリシーや環境指定による競合を確認して「保存」を選びます。
5. 保存後の表示を確認します。「キャンセル」は未保存の編集内容を破棄します。

ほかの操作で設定が変更されていた場合、保存は競合として拒否されます。再読み込みして差分を確認し、再度プレビューしてください。
既に作業中の担当者を設定変更で入れ替えることはできません。現在の作業を完了または既存の引き継ぎ手順で整理してから変更します。

## 認可と適用範囲

- 未認証のローカル閲覧と読み取り専用ユーザーは設定を変更できません。
- 保存は管理者権限、同一オリジン、サーバー側で解決したテナント・組織・プロジェクト範囲を検証します。画面から送ったスコープ値は権限の根拠になりません。
- 推論のユーザー設定は共有グローバル設定です。範囲を限定された管理者が、ほかのテナント等に影響するグローバル設定を書き換えることはできません。
- ミッションの選択設定は既存のチーム構成に保存され、再構成・再配置でも保持されます。
- 推論の設定は既存の設定保存・監査・バックアップ・ロールバック経路を使います。認証・スコープ・CSRF・更新競合の確認を通った保存だけが、専用の `reasoning_settings_writer` 権限で設定本体・直前のバックアップ・履歴を書き込みます。この追加権限は認証情報や他の設定ファイルを許可しません。
- この画面では認証情報、アカウント、権限ポリシーを登録・変更しません。

## 対象外

この設定はミッションの担当選択と推論ロールの経路を対象にします。
dot の実行エンジンや JEV の判断プロバイダーを包括的に統一するものではありません。
プレビューの準備状況は実行時の可用性を保証しません。固定対象が後で利用できなくなった場合も、別の対象へ黙って切り替えず失敗を返します。

固定経路を保証できない reasoning dispatcher 経由の実行モードでは、固定設定を利用不可として扱います。実行時に別経路へ迂回して成功扱いにすることはありません。プレビューに示された競合・非対応理由を解消してから保存してください。

推論画面の「解決された選択」は、キャッシュ済みの準備状況に基づく設定の解決結果です。実行中の長寿命バックエンドの再起動・再選択完了を意味しません。固定対象を変更した場合は、既存のバックエンド再選択またはプロセス再起動を行うまで、その古い固定経路の呼び出しを拒否します。Agy の明示モデル固定も、実行アダプターがモデル指定を保持できないため非対応です。

ミッションの固定担当は `agent_runtime` 実行経路に対応します。CLI サブエージェント経路では対象の固定を保証できないため、実行時に拒否します。設定画面に表示される対応経路を確認してください。通常の自動実行モードを、この設定によって変更することはありません。

ミッション画面では、保存済みの担当者と現在の適格性を別々に表示します。候補の評価が変わっても保存済みの担当者を変更済みとして表示しません。プレビュー後に候補の評価が変わった場合も、そのプレビューのまま保存できません。

## 準備状況の読み方

CLI の候補には有効期限内の検出キャッシュが必要です。キャッシュがない、または古い場合は利用可とは判定しません。API・ローカル接続型の候補は設定済み環境情報の存在を確認しますが、接続や資格情報の有効性を実際に検証した表示ではありません。プレビューは secret store から資格情報を展開しません。そのため、資格情報が secret store のみにあり、利用可能性の読み取り専用証拠もない候補は利用不可と表示されます。通常の運用手順で準備状況を更新してから再度プレビューしてください。

## 検証

選択設定のブラウザーシナリオは既存 GitHub Actions CI（`CI=true` かつ `GITHUB_ACTIONS=true`）の Playwright 対応 Operator テスト経路で必須実行します。ローカルのテストでは GitHub Actions 専用ブラウザーテストが明示的にスキップされます。これはブラウザー検証の成功を意味しません。CI では Chromium が起動できない場合もテスト失敗とし、スキップしません。
