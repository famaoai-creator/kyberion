# Concierge の成果ファイルを取得する

成果カードのファイル一覧から、元のファイルを取得できます。インラインのプレビューは従来どおり先頭5件までです。ダウンロード用の一覧は別にページ送りし、PDF、DOCX、長いテキストなども対象にします。新しいファイルの生成、承認、実行、成果の受領処理は行いません。

## 対象と既存の権限

この導線は、既存の mission に所属する成果を、そのテナントの現在有効な owner メンバーが読むためのものです。最初の依頼者だけに限定する所有権モデルではありません。ローカル接続や未登録 localadmin のフォールバックを owner の証明にせず、現在のメンバー登録と所属を毎回確認します。

- inbox entry の mission から、現在の正式な tenant、organization、project、tier を解決します。クライアントのパラメーターやファイル名は権限の根拠になりません。
- viewer の許可範囲と、既存の surface 読み取りポリシーの両方を確認します。organization / project の制限があるのに成果側の情報がない場合も許可しません。
- mission の保存場所と state の tier / tenant が矛盾する場合、古いキャッシュを根拠に許可しません。
- 対象はその mission 配下の deliverables、artifacts、outputs、evidence に記録されたファイルです。これは既存の mission-asset の成果領域に合わせた範囲です。
- personal tier、正式な tenant のない成果、mission に結び付かない inbox entry、成果領域の外のパスは対象外です。承認や新しい共有権限を自動追加して取得可能にすることはありません。

## 取得と失効

一覧と取得は同一 origin の読み取り専用 GET です。URL は entry に結び付いた不透明な識別子だけを受け取り、物理ファイルパスを入力・公開しません。一覧の時点の entry、利用者の範囲、正式な所有スコープ、内容のハッシュに結び付き、変更後の古いリンクは拒否します。

ダウンロード時にも現在のメンバー、所属、viewer 範囲、mission を再確認します。シンボリックリンク、パス逸脱、削除、読み取り中の置換・変更、ハッシュ不一致は取得失敗になります。検査した同じバイト列を返し、検査後にパスを開き直して配信しません。応答は attachment、no-store、nosniff で、HTML等の能動的コンテンツを画面へ埋め込みません。

一覧を閉じる・別の成果へ移動する間に古い応答が届いても、閉じた一覧や別の成果へ反映しません。権限失効や一覧の変更があった場合は、一覧を開き直して現在の状態を確認してください。

## 上限と制約

- 1ファイル16 MiBまで。上限超過を一部だけ成功として返しません。
- 一覧は1ページ10件、1 entry は最大1,024件。上限を超えた entry は明示的に拒否します。
- 未存在・対象外のファイルは取得不可として表示します。プレビューの制限を増やしたり任意のパスを生成したりしません。
- 安全な no-follow ファイル読み取りを提供できない環境では fail-closed です。
- ファイル記述子と開く前後の inode・サイズ・ナノ秒単位の更新／変更時刻を照合します。ルートから全祖先ディレクトリの inode・更新／変更時刻も固定して照合し、通常の移動・リンク置換を元に戻す操作も拒否します。これは openat による原子的なパス走査ではありません。ファイルシステムの識別子や変更時刻を特権的に偽装・巻き戻しできる主体に対する保証はありません。
- 公開範囲と所有権はサーバー側の既存ポリシー・状態を信頼します。サーバー管理者自身による状態やポリシーの改変に対する独立した証明ではありません。
- この実装はログイン資格情報やメンバーを準備しません。実際の本人によるログイン・承認の確認は、既存の正規 IdP とメンバー紐づけがある環境で別途行います。
