# 最初のローカル診断を試す

プロフィール登録、実行設定、人間の承認は別の状態です。プロフィールの保存や baseline の all_clear は、仕事の実行権限を意味しません。

## 1. ホームから確認する

Presence Studio のホームにある「最初の仕事」から `/first-job` を開きます。初期状態では設定不足を表示します。画面を開く・更新するだけでは、テナント、依頼、承認、実行は作成されません。

この入口は固定の公開診断データ専用です。自由文、既存の機密情報、外部 AI、外部配信を扱いません。通常の Concierge へのフォールバックもありません。

## 2. オペレーターが明示的に設定する

通常のオンボーディングとビルドを完了した環境で、新しい検証専用テナント名を選びます。進行中の mission や別テナントの実行コンテキストから設定しないでください。

```bash
pnpm onboarding first-job --tenant my-public-diagnostic --json
```

これは読み取り専用の計画です。内容と `plan_digest` を確認してから、表示されたダイジェストを指定します。

```bash
pnpm onboarding first-job --tenant my-public-diagnostic --apply --accept-plan <plan_digest> --json
```

作成対象は検証専用テナント、public の固定診断 charter、およびその1件に結び付く利用者・パイプラインの対応付けです。組織やプロジェクトは作りません。既存の無関係なテナントや変更済み設定を再利用せず、paused/retired の dot を自動再開しません。認証資格情報、人間のメンバー、承認記録は作成しません。

計画後に設定が変わると適用を拒否します。途中で失敗した場合は、残った設定を確認して計画を取り直してください。既存データを消してやり直す操作ではありません。

Presence の通常起動には別の owner メンバー初期化があります。owner が未作成の環境では、既存テナントへの owner membership が追加され得ます。画面を読むだけの起動と考えず、管理者がこのアクセス付与を事前に確認してください。first-job の設定コマンド自体はこの処理を行いません。

## 3. 実際の人間としてサインインする

loopback の localadmin 接続だけでは人間の承認を証明できません。既存の [OIDC ログイン設定](SURFACE_OIDC_LOGIN_OPERATIONS.ja.md) と、有効な Kyberion メンバーへの外部 ID の結び付けが必要です。そのメンバーは画面の利用者と一致し、対象テナントの owner または approver である必要があります。

認証設定がない場合、画面は不足を表示します。セットアップコマンドがサインインを代行したり、資格情報を生成したりすることはありません。認証設定には別途、正規の管理手順が必要です。

## 4. 依頼、承認、実行、確認

1. 画面の固定診断を依頼します。
2. オペレーターが `pnpm onboarding first-job --tenant my-public-diagnostic --tick` を実行します。承認待ちになるまでの取り込みも、この明示的な処理で進みます。
3. サインインした本人が画面で対象、効果、期限を確認し、その1件を承認または却下します。
4. オペレーターが同じ tick を実行します。承認は自動生成されず、期限・設定・メンバー・署名が再確認されます。
5. 画面を更新して結果を確認します。tick の成功表示だけでは成果の完成を意味しません。

現在の画面が表示する成果は、検証済みのメタデータ（形式、ハッシュ、依頼・改訂の識別子等）です。成果ファイルの本文を閲覧・ダウンロードする導線はありません。ローカルのファイル内容・ハッシュ確認はオペレーター側の検証になります。

形式変更の依頼は親成果に結び付き、改めて個別承認を必要とします。再読み込みしても承認を再利用したり、新しい依頼を自動作成したりしません。

## 停止・期限切れ・復旧

期限切れ、署名失効、設定変更、不確かな実行状態では処理を保持します。画面にはオペレーター確認が必要と表示されます。現時点で、その保留を画面から安全に解消して新規依頼へ戻る一貫した導線はありません。手動確認が必要です。既存の監査や依頼を消す、承認を書き換える、一般処理へ切り替える操作で回避しないでください。

## 信頼境界

署名は、構成済みサーバーのブラウザーセッション署名鍵を用途分離して利用します。クライアントの「認証済み」という申告やチャットの文字列は承認証明になりません。サーバーの鍵・ファイルを自由に変更できる主体に対する独立した耐改ざん証明ではありません。

診断の本体はローカル限定ですが、本人確認の OIDC ログイン自体は構成済み IdP と通信します。ローカル診断と外部認証を混同しないでください。
