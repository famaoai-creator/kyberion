# Skill Recorder 概念取り込み フェーズレビュー

## 結論

DR-01〜DR-09 は実装完了と判定する。各フェーズで、実行境界・秘密境界・意味層・再利用成果物の順にレビューし、対象テストと型検査を通した。

## Phase 1 — 承認分類と desktop executor（DR-01 / DR-02）

判定: **PASS**

- `desktop:destructive_action` を approval policy と `RISKY_OPS` に登録した。
- read-only desktop op は承認なしで進み、未知または破壊的 op は承認要求へ落ちる boundary test を追加した。
- `procedure-dispatcher` は既存 OS automation bridge を実行面へ接続し、approved recording、対象 window、AX focused input の再確認に失敗した場合は停止する。
- 古い「OS automation backend が無い」という schema/dispatcher 注記を是正した。
- `knowledge/personal/browser-procedures.json` の全 `pipeline_ref` に対応する `pipelines/browser/*.json` を復元した。

証拠: `libs/core/risky-op-registry.test.ts`、`libs/core/procedure-dispatcher.test.ts`、`pnpm run check -- --scope full --only contract-schemas`、`pnpm run typecheck`。

## Phase 2 — 観測 tier/cost と人間実演 recorder（DR-04 / DR-03）

判定: **PASS**

- `DESKTOP_OBSERVATION_SOURCES` を tier 0/1/3、cost、permission、captures の単一 registry とした。
- recorder、baseline-check、doctor が同じ registry/readiness 判定を参照する。利用不可ソースは理由付きで表示し、clipboard 本文は hash のみ保持する。
- polling recorder は executor を呼ばず、アプリ/window/host 境界で step をまとめる。
- frame は変化または heartbeat のみ保持し、ブラウザ前面時の間隔を延ばす。
- 座標だけの観測には `needs_semantic_resolution` を付ける。

証拠: `libs/core/desktop-recording.test.ts`、baseline の `desktop_observation` report、doctor の Desktop observation 表示。

## Phase 3 — 意図再構成と native op 優先（DR-05 / DR-06）

判定: **PASS**

- recording と compilation の間に、intent、順序付き steps、evidence、confidence、human review を持つ `desktop-intent` 層を追加した。
- stub でも決定論的な baseline intent を生成できる。
- 観測→op 対応表は actuator registry の実在 op を検証し、GitHub 等は native op を優先、API/CLI が無い対象だけ GUI fallback とする。

証拠: `libs/core/desktop-recording.test.ts`、`knowledge/product/orchestration/observation-to-op-map.json`、`native-op-mapping.ts`、`pnpm check -- --scope full --only eval-distill`。

## Phase 4 — frame redaction と egress（DR-07）

判定: **PASS**

- OCR は座標取得に限定し、PII rule の検出領域を不透明矩形で塗り潰す。
- 高エントロピー形状は frame 経路だけに適用し、text 経路には適用しない。
- known sensitive text の cross-feed、スキャン失敗時の frame/text withhold、egress の一点ゲートを実装した。
- browser extension は hand-written scrubber を廃止し、generated PII rule を注入する。

証拠: `libs/core/frame-redaction.test.ts`、`pnpm check -- --scope full --only eval-distill`、`tools/adf-replay-extension/pii-rules.generated.js`。

## Phase 5 — eval と trace→ADF candidate（DR-08 / DR-09）

判定: **PASS**

- `pnpm eval:distill` は production の recording、intent、native mapping、redaction を import して score 1.0 / hard failures 0 となった。
- native-op と GUI fallback の両シナリオ、redaction recall hard gate、soft overmask、xfail/xpass を固定した。
- `target_kind: procedure` と trace provenance 付き draft ADF を追加し、schema/guardrail preflight を通す。
- draft は `_draft: true` であり、human review による promotion 前は execution catalog に載せない。procedure を通常の promoted memory と混同しないよう separate gate を置いた。

証拠: `libs/core/trace-procedure-candidate.test.ts`、`libs/core/promoted-memory.ts`、`pnpm run check -- --scope full --only contract-schemas`、`pnpm run build`。

## 横断レビューと制約

- `pnpm run typecheck`、対象テスト、contract/catalog/op-registry/script-integrity、build、reference drift、doc examples は通過した。
- 追補後の `pnpm exec vitest run libs/core/` は 4,765 passed / 27 failed / 1 skipped。失敗は既存の mission fixture の `Persona 'unknown' with authority role 'forks'` 23件、failover fixture の knowledge-sync-rules 不在 3件、既存 I18N-05 timeout 1件で、DR の対象テスト失敗ではない。全体を green とは扱わない。
- 実 macOS の画面収録権限付き物理操作 E2E はこの実行環境では実施していない。実 bridge の permission/readiness surface と注入 bridge による決定論テストまでを本実装の証拠範囲とする。
- `check:entity-governance` は `status: ok` / `plan_ledger.missing: []` だが、既存 workspace registry 警告（未登録・不足 project workspace）があるため終了コードは 1。DR の計画登録欠落ではない。

## レビュー引き渡し

コードレビューでは、(1) desktop approval boundary、(2) recording に生値を残さないこと、(3) egress fail-closed、(4) trace candidate の human-only promotion の4点を重点確認する。

## 追補レビュー — 2026-08-10

前回レビューで検出された実装上の残課題は、次の通り修正済みとする。

- 画面録画は `redactScreenVideoFrame` を必須のフレーム境界とし、OCR・PII 座標で秘匿化できないフレームは MP4 に入れない。capture 側の raw 一時ファイルも `finally` で削除する。
- desktop event の `params` は `press_key.key_code` だけを許可し、AX/ウィンドウ文字列・evidence は PII/secret scrub を通す。永続 recording の再検証でも未許可パラメータと未スクラブ文字列を拒否する。
- feed の最終状態を採用し、poll failure 時に初期 active 状態へ戻らない。意味解決未完了の step は compile・promotion・dispatch の全境界で拒否する。
- native-op mapping を intent reconstruction の実行経路へ接続し、native op と GUI fallback を本番 import の deterministic eval で確認する。空の fixture が green になることも防止した。
- trace candidate の promotion は procedure catalog/pipeline を生成したことを意味しないため、`executable: false`、`promotion_ready: true`、`next_gate: procedure_catalog_promotion` を明示する。
- desktop promotion は prepared/committed marker を持つ二段階 transaction とし、未完了 marker がある catalog entry は registry から隠す。doctor の新規 desktop observation 表示は vocabulary catalog 経由にした。

追補の検証証拠: `pnpm run typecheck`、対象 Vitest 5 files / 21 tests passed、`pnpm eval:distill` score 1.0 / hard failures 0、`pnpm run check -- --scope pr --only esm`、`pnpm check -- --scope full --only vocabulary-types`、`pnpm check -- --scope full --only pseudo-locale`、`pnpm check -- --scope full --only i18n`、`pnpm check -- --scope full --only pii-rules`、`pnpm check -- --scope full --only catalogs`、`pnpm run check -- --scope full --only contract-schemas`、`pnpm check -- --scope full --only op-registry`、`pnpm run check -- --scope pr --only script-integrity`。
