- **New `modeling:terraform_asset_inventory` op** — classifies a Terraform tree into an `IaCAssetInventory` IR: provider/module/DNS-derived external services, public-exposure candidates with attribute-level evidence (`EXPOSURE_*` signals), open-ingress findings with sensitive-port flagging, cross-provider attachment joins (`EXPOSURE_VIA_OPEN_SG`/`_NSG`/`_FIREWALL` for AWS SG refs, Azure NSG associations, GCP target_tags), backends (incl. `terraform_remote_state`, `cloud {}`), and unresolved dynamic references instead of guessed verdicts. Classification is a declarative `RESOURCE_RULES` table — new resource types are rules, not dispatcher edits — and the IR is IaC-agnostic so future extractors (CloudFormation, Pulumi, CDK) share the generic sections. Runnable via `pipelines/terraform-asset-inventory.json`. `terraform-topology` block parsing now also sees label-less `terraform { ... }` blocks, so backends and `required_providers` are captured.
- **New `modeling:asset_inventory_to_ledger` op** — maps an `IaCAssetInventory` onto the canonical external-asset ledger schema (`external-asset-inventory.md` Phase 2) as a review-pending draft: `svc:` entries for services, `asset:` entries for published apps, data stores (incl. Terraform state backends), network controls, and identity documents; evidence/signal provenance and endpoint references (`${aws_elb.x.dns_name}` outputs, DNS targets) preserved; shadow flags per the procedure rule (unknown owner/contract). Runnable via `pipelines/external-asset-ledger.json` (inventory → ledger chain). Rules can opt into `data` blocks via `kinds`, which is how `aws_iam_policy_document` wildcards are detected; mixed literal+reference CIDR lists, GCP EGRESS/disabled firewall rules, `prefix_list_ids`, AKS/GKE default-public control planes, EMR `visible_to_all_users`, and `route`/`route_table` → internet-gateway joins (`EXPOSURE_IGW_ROUTE`) are handled; `security_group_id` matching uses a word boundary so `referenced_security_group_id` (source SG) is never mistaken for the rule target.
- **New `pnpm security:ledger` ceremony + `libs/core/security-asset-ledger`** — the governed registry path of `external-asset-inventory.md` Phase 2: a tenant-scoped append-only JSONL ledger at `knowledge/confidential/{tenant}/security/external-assets.jsonl` (tenant-registry resolved, fail-closed, schema-validated per append). `promoteSecurityLedger` merges drafts the safe way — governance fields (owner/contract/MFA/data classification/review status) carry forward from the verified head, observation fields refresh, unchanged entries write nothing, absent entries are reported `not_observed` and never auto-retired. `retireSecurityAsset` is the explicit logical-deletion ceremony. CLI: `--draft`/`--verify`/`--retire`/`--list`/`--lineage`/`--dry-run`; anonymous writes refused via the same tier-guard identity contract as `knowledge:ingest`.
- **Phase 3 — exposure check + check evidence** — `check_results` is now a first-class ledger field (`security-asset-record.schema.json`); `recordCheckResults` applies batch check outcomes (one version per service, latest per `check_id`, history in the version chain, unknown services reported not created); `pnpm security:ledger --record-checks <file>` is the ceremony; `security:ledger --report` prints the `exposure × data_classification` matrix + shadow/pending/critical(public×personal) lists. New ops: `network:exposure_check` (batch endpoint probe — per-item try/catch so an unreachable endpoint is a finding, not a crash; HTTP error status still counts as reachable) and `modeling:security_ledger_check_plan` (tenant ledger → check items, same tier-guard as the CLI). Runnable via `pipelines/exposure-check.json`; writing results back stays a human ceremony.
- **Phase 4 — IPA obligation tracking** — `requiredChecksFor(entry)` maps ledger categories to the immediate-check items of the IPA checklist (published-app → A-1/A-2/A-3 when public, SaaS/cloud/vpn/api-integration → B-1/B-2/B-3, data-store → C-1, network-control → B-2, identity → B-3); `modeling:security_ledger_check_plan` now emits `obligations` with `probe`/`manual` kind and `done`/`missing` status (probe obligations attach to endpoint-bearing services); `security:ledger --report` gains `ipa_check_coverage` (per-check-id done/missing) + `coverage_gaps` + `critical_public_sensitive` (public × personal|confidential) + `public_unclassified` lists; `recordCheckResults` skips identical re-records (`unchanged`) and stamps `checked_at` when absent.
- **Review-cycle fixes (Phase 3/4)** — `recordCheckResults` now stamps `checker`/`checked_at` when absent, byte-identical re-application is a no-op while a fresher `checked_at` refreshes recency; public `data-store` entries gain the `A-2` log-anomaly obligation (S3-public = the primary IPA leak vector); `checkStatusFor` + `CHECK_STALE_DAYS` (90d) add a shared `done`/`stale`/`missing` status — stale or undated checks count as missing in `--report` coverage_gaps and surface in `stale_checks` + check_plan obligations; `--record-checks` accepts a bare array or `{checks: [...]}`.
- **Phase 5 — shadow disposition approvals** — `security:ledger --request-approvals` files one `mission_gate` approval request (terminal channel) covering all shadow-flagged heads; the printed request id feeds `--approval-id` on the subsequent `--retire`/`--set` disposition calls. Fixture/test runs preview only (never file into the global approval store).
- **Phase 6 — steady-state cadence** — `pipelines/exposure-check.json` carries a `schedule` (quarterly, 1st 06:00 Asia/Tokyo); tenant deployment follows the tenant-scheduled rule (`knowledge/confidential/{tenant}/pipelines/` + project-trust approval). The orphan baseline entry was dropped once the schedule made the pipeline reachable.
- **Review-cycle fixes (Phase 5/6 + evidence semantics)** — `mergeCheckResults` picks the record with the later `checked_at` (a stale checks file can never roll back a fresh observation); `checkStatusFor` treats future-dated and undated `checked_at` as `stale`; `security:ledger --request-approvals` is idempotent (existing pending request for the same correlation is returned, not duplicated); `--retire` on a shadow-flagged entry without `--approval-id` prints an audit-link warning.
