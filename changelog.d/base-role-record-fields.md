- **Stored records and inputs name the base role and Org Role directly** (concept model v2 S4). Pipeline run journals now store `execution_authority.base_role` and `library_execution.identity.base_role` (formerly `persona`). The authn agent-context input is `executionContext.baseRole` (formerly `persona`). The mission team plan (`team-composition.json`) stores the mission's Org Role as `org_role` (formerly `assigned_persona`, the mission-state name). `scripts/compose_mission_team.ts` takes `--org-role` (formerly `--persona`), and `POST /api/ops/plan-preview` takes `orgRole` (formerly `assignedPersona`). Writers emit only the new names. For one release the old names are still read: when the new name is absent, or with a warning for `--persona`. When both are present the new name wins, so records written before this change resume and load the same way. `tests/fixtures/base-role-record-fields-equivalence.json` replays them. The helpers are renamed to `inferBaseRoleFromRole`, `resolveExecutionBaseRole` and `executionBaseRoleText`, and the execution scope field to `assumedBaseRole`. The published `inferPersonaFromRole` and `resolveExecutionPersona` stay one release as deprecated aliases. `mission_controller start --persona` is unchanged.
