- **Opening confidential egress now needs a human approval** — a `training_use: none` provider attestation is recorded only under an approved request: `pnpm onboarding llm attest --tenant <slug> --provider <id> --training-use none --plan … --basis … --attested-by … --request-approval`, then a human runs `pnpm kyberion approvals --approve <id>`, then the same command with `--apply --accept --approval-request-id <id>`. The request is bound to the exact tenant/provider/claim, must be approved by an authenticated human, unexpired (72h) and unused; the `tenant.attest_provider` audit entry names the invoking actor and the approver. `used`/`unknown` (which never open egress) still need only `--apply --accept`.
- **Behaviour change: `pnpm tenant attest-provider`** follows the same rules — it writes only with `--apply --accept` and needs the approval flow for `--training-use none`. Both paths refuse to attest for another tenant from a tenant-bound process and cap `--valid-for-days` at the policy `attestation_ttl_days` (180).
- **Onboarding LLM fixes** — `pnpm onboarding llm select --apply` audits the invoking actor (not the facade's elevation) and rewrites `.env.local` atomically, touching only `KYBERION_REASONING_BACKEND`, keeping the file mode (new files 0600) and printing the change. `show` and `tenant:activation plan` report the effective tenant, the rule that allowed each provider and the gate's denial reasons. The interactive `pnpm onboarding` wizard asks for the model after the backend and offers an opt-in (default no) attestation step that only opens the approval request for `none`.
