- **Intent heuristics read a locale-keyed phrase lexicon** — the ~110 hardcoded Japanese/English `/…/i.test()` literals behind intent classification (browser conversation commands, task-session payload hints, contextual intent frames, intent resolution scoring, execution / guided-coordination briefs, mission role hints, procedure self-repair) now resolve concept ids through `matchesIntentPhrase(text, conceptId)` (`@agent/core`). Phrases live in `knowledge/product/governance/intent-phrase-lexicon.json` (schema `intent-phrase-lexicon.schema.json`), keyed by locale; all locales are checked by default, so adding a language is a JSON edit. Decisions match the captured old regex outputs (parity test) except for two intentional behavior fixes: (1) `browser.control_command` — the old `/^(止めて|停止|…)\b/i` literal never matched a Japanese command on its own, so 止めて / キャンセル / 停止して are now control commands; Japanese command words carry a Japanese-aware trailing guard (end, whitespace, punctuation, or a polite suffix from the lexicon's `prefix_word_suffixes` such as して / ください), so 停止ボタンを押して / キャンセルボタンをクリック / 再開ボタンを押して still click the named button; (2) `contextual_frame.subject_self` — English pronouns are whole words, so `me` no longer matches inside `meeting`. The compiled matcher is memoized per lexicon path and re-checks the file at most every 2 s (`INTENT_PHRASE_LEXICON_RECHECK_MS`) or after `resetIntentPhraseLexiconCache()`, and the execution-feedback reply pattern is compiled once per matcher. Nested quantifiers are rejected at compile time; the schema documents the shapes that guard cannot detect, a smoke test runs every concept against adversarial 5,000-character inputs under a time budget, and the two cubic `browser.input_text_extract` patterns (`"(.+?)".*…`, `「(.+?)」を.*…`) now use negated classes.
