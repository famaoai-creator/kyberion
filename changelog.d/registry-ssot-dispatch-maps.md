- **Coordination routing and executor registries (RS-07)** — coordination kind → actuator routing and execution-brief overrides live in `knowledge/product/governance/coordination-actuator-routing.json`, validated against the actuator manifest catalog; non-actuator components (`task-session-manager`, `intent-compiler`, `virtual-camera-bridge`, `service-orchestrator`) move from `target_actuators` to the new `suggested_support_components` / `support_components` fields. Procedure dispatch uses an executor registry plus `<substrate>:<execution_substrate>` routes instead of a switch.
- **Op dispatch handler maps (RS-07)** — the system (capture/control), browser (capture/transform/apply) and modeling (all step types) op switches are replaced by exported handler maps keyed by op name (mechanical move, behaviour unchanged; two unreachable duplicate `window_list` / `chrome_tab_list` cases dropped). Tests assert the map keys match the actuator op registry, with reviewed exceptions listed explicitly.
- **Provider descriptor follow-ups** — capability probe commands/flags and KD-05 permission-profile projections move from code tables keyed by provider id into `reasoning-providers/*.json` (`cli.capability_probe`, `cli.permission_profiles`); `generate:env-registry` also discovers `KYBERION_*` names declared only in provider descriptors (`env_keys`, `model_env_keys`, `bin_env_key`); the Telegram long-polling bridge forwards to `TELEGRAM_BRIDGE_PORT` when set; `operator-surface`, `personal-pads` and `terminal-hud` are covered by the role-assumption policy and reachability report (the analyzer now resolves `pnpm <script>` and package `dist/` entry points).
