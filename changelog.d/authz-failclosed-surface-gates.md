category: Security

- **Concierge pipeline launch and schedules** — launching a catalog pipeline (`POST /api/ops/pipelines/run`, Automation › Pipelines) and registering, changing, removing or running a schedule of one (`/api/ops/schedules…`) now require an all-tenant localadmin viewer or the installation owner signed in with a browser session (on this machine, or with a recent passkey step-up from another device). On a server bound to a tenant (`KYBERION_TENANT`, or the scope saved by `pnpm scope use`) the signed-in owner keeps these controls. A credential-less local request also keeps them while first-run setup is unclaimed or `KYBERION_CONCIERGE_ALLOW_ANONYMOUS_LOOPBACK` is on; once an owner is bound it is answered 401 as before, like every other route. Refused with 403: a registry token (its registration always lists its own tenants, even when bound to the owner member), the env localadmin token on a tenant-bound server, and any other member; the Pipelines page hides the run control for them. A pipeline `context` (request body, schedule, stored schedule) may no longer set keys the runner derives itself (`_knowledge_scope`, `mission_dir`, `mission_tier`, `mission_evidence_dir`, `trust_resolved`, `project_trust_approval_id`, `repo_root`, `__*`, …): the routes answer 400, and the scheduler records such a schedule as failed instead of running it — remove the keys from the schedule.
- **Concierge A2A relay** — the `a2a` action of `POST /api/ops/agents` validates the envelope against the A2A envelope schema before routing (400 otherwise; `a2a_version`, `header.msg_id`, `header.sender`, `header.performative` and an object `payload` are required). A tenant-scoped viewer may relay only an envelope whose `payload.context.security_scope` names exactly one tenant inside its scope; no scope, another tenant, conflicting aliases, or a `context.mission_id` that differs from the scope's `mission_id` get 403.
- **MCP actor identity** — `kyberion.approval.decide`, `kyberion.audit.export` and `kyberion.audit.verify` attribute the action to the server-bound MCP principal (`KYBERION_MCP_PRINCIPAL`). The `decided_by` / `requested_by` arguments are still accepted but are recorded only as `caller_label` in the audit entry; set `KYBERION_MCP_PRINCIPAL` if you rely on a meaningful decider name.
- **Presence Studio tenant hint** — on loopback, `?tenant=` / `x-kyberion-tenant` must name a registered tenant (or the server's own `KYBERION_TENANT`); any other slug gets 403 instead of becoming the viewed tenant. `/api/me` ignores such a hint so a page with a stale stored tenant recovers by itself.
- **Presence Studio approval inbox** — `GET /api/approvals` no longer lists other tenants' requests to a viewer narrowed to a tenant. An all-tenant loopback owner sees what it saw before; a loopback owner with `KYBERION_TENANT` set or a tenant selected sees that tenant's requests plus requests that carry no tenant; a remote token viewer sees only its tenant's requests.
- **Agent runtime supervisor transport** — with `KYBERION_AGENT_RUNTIME_SUPERVISOR_TRANSPORT=tcp` the daemon refuses to start unless `KYBERION_AGENT_RUNTIME_SUPERVISOR_TOKEN` is set, and it refuses a `KYBERION_AGENT_RUNTIME_SUPERVISOR_SOCKET_PATH` that reads as a number (Node would open a TCP port on every interface). The default local IPC transport (Unix socket / named pipe) is unchanged.
