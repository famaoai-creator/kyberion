- **Customer decision store rules hold at the guard, not only in the store** — the tier guard now checks the content of every `customer_decision_consumer_store` and `customer_decision_milestone_store` write against the record on disk, so a process that builds the capability itself and calls `safeWriteFile` is held to the store's rules: consumer locks keep their identity, `rework` records and `task_proposal` entries (a new `resolved` must name an operator-confirmed customer decision), a hold is never dropped, and an agenda only gains `milestones_passed`. Writes without content (append, copy, rename, link, unlink) are refused for both roles. Lock rewrites keep rework records and resolved holds.
- **Narrow roles replace borrowed broad ones** — the CD-10 bolt rejection and the CD-11 hand-off / manual reminder inbox tasks are written as the new `deliverable_inbox_writer` (the inbox entries file and its own lock only, append-only: the guard keeps every existing entry byte-identical; previously `surface_runtime`, which can write all of `active/shared/runtime/`), and an archived bolt's state is read as the new tenant-bound, read-only `archived_mission_state_reader` inside its one-file capability (previously `mission_controller`). `pnpm kyberion customer-channel bind|unbind` writes the bindings file as the new tenant-bound `customer_channel_binding_store` (that one file only; previously `customer_create`).
