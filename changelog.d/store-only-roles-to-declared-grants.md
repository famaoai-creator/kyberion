- **Store-only Authority Roles become declared store grants (S4 slice 3)** — a store facade now issues its store's grant with `withStoreGrant` / `withStoreGrantAsync` (libs/core/authority.ts) instead of assuming a store-only role. The grant's operations are declared in security-policy.json `store_grants` (the former role's `allow_read` / `allow_write` / `deny_read` / `narrow`, unchanged) and its names in `foundation/declared-store-grant.ts`; it has no Authority Role card, is not in the role index or `authority_role_permissions`, is refused by `withExecutionContext`, and only a token the facade opened resolves it. Issuance uses the same RA-02 rule (the name stays in role-assumption-policy as the issuance right) and the same tenant binding rule. Every converted name has a before/after (principal, path, operation) equivalence matrix (`libs/core/testing/store-grant-equivalence.test.ts`, fixture `tests/fixtures/store-grant-equivalence.json`). Intentional narrowing: a process running as the name through `SYSTEM_ROLE` / `MISSION_ROLE` / a delegated child env, or a child process spawned inside the grant, now gets no I/O (`[STORE_GRANT_REQUIRED]`) instead of the former role's permissions. Converted: `scope_locale_reader`, `peer_catalog_reader`, `peer_task_artifact_writer`, `first_job_tenant_status_reader`, `chronos_token_registry_reader`, `nhi_accountability_reader`, `reasoning_settings_writer`, `metrics_cap_reader`, `operational_learning_writer`, `customer_decision_deal_note_writer`, `credential_allocation_reader`, `tenant_ledger_store`, `delegation_record_store`, `tenant_approval_store`, `tenant_approval_partition_index_reader`, `audit_mirror_writer`, `ops_alert_store`, `workspace_tenant_registry_reader`, `workspace_tenant_registry_index_reader`; per the owner decisions of 2026-11-10, the deny-only `deliverable_inbox_writer`, `customer_channel_binding_store` and `archived_mission_state_reader` (their `narrow` declarations are now explicit deny declarations in `store_grants`), the flow writers `concierge_management_writer` (issued per write by the management facade) and `dot_charter_store` / `dot_lifecycle_runtime_store` (the decomposed `dot_lifecycle_writer`, issued per write by the dot lifecycle facade), and the cross-store readers `workspace_graph_reader`, `concierge_management_reader` and `peer_responder_reader`, which are audited disclosures: each issuance records `store_grant.disclosure` in the audit chain first and is refused when that record fails (`[STORE_GRANT_DISCLOSURE_UNAUDITED]`); a facade that opens one inside its own exact resource ceiling records it before entering the ceiling (`recordStoreGrantDisclosure`, one-shot receipt). The disclosure record (grant name, principal, bound scope, operation — no tenant content) is a system-scope entry: it carries no tenant stamp (the bound and caller tenants are metadata) and lands in the master chain only, never a tenant mirror, so a multi-tenant surface whose ambient tenant differs from the grant's tenant records it too; it is appended by the audit chain's own store writer outside any request ceiling the caller is in (`auditChain.recordDurable`, whose master-chain write must land), so a disclosure opened from inside an exact resource ceiling (the information-asset catalog) is recorded too, and a record that does not land refuses the read; the caller's own I/O keeps its ceiling. Names of declared store grants are reserved for new roles (`pnpm organization role create`), and a role entry under a grant's name never changes what the grant permits.
