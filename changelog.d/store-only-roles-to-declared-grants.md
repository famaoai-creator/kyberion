- **Store-only Authority Roles become declared store grants (S4 slice 3)** — a store facade now issues its store's grant with `withStoreGrant` / `withStoreGrantAsync` (libs/core/authority.ts) instead of assuming a store-only role. The grant's operations are declared in security-policy.json `store_grants` (the former role's `allow_read` / `allow_write` / `deny_read` / `narrow`, unchanged) and its names in `foundation/declared-store-grant.ts`; it has no Authority Role card, is not in the role index or `authority_role_permissions`, is refused by `withExecutionContext`, and only a token the facade opened resolves it. Issuance uses the same RA-02 rule (the name stays in role-assumption-policy as the issuance right) and the same tenant binding rule. Every converted name has a before/after (principal, path, operation) equivalence matrix (`libs/core/testing/store-grant-equivalence.test.ts`, fixture `tests/fixtures/store-grant-equivalence.json`). Intentional narrowing: a process running as the name through `SYSTEM_ROLE` / `MISSION_ROLE` / a delegated child env, or a child process spawned inside the grant, now gets no I/O (`[STORE_GRANT_REQUIRED]`) instead of the former role's permissions. Converted: `scope_locale_reader`, `peer_catalog_reader`, `peer_task_artifact_writer`, `first_job_tenant_status_reader`, `chronos_token_registry_reader`, `nhi_accountability_reader`, `reasoning_settings_writer`, `metrics_cap_reader`, `operational_learning_writer`, `customer_decision_deal_note_writer`, `credential_allocation_reader`.
