category: Fixed
---

- **Re-evaluated modules no longer break seam registration in tests.** Under Vitest, a module that defines a core seam at load time and is evaluated a second time (for example after a module-registry reset) now replaces its own catalog entry and logs a warning, instead of failing with `Seam <key> is already registered in the catalog`. A seam defined by any other module under the same key is still rejected, and outside Vitest every duplicate registration still fails with `SEAM_DUPLICATE_PROVIDER`. Seam definitions in `coreSeamCatalog` must declare `owner: '<repo-relative path of the defining module>'`; `libs/core/seam-reevaluation.test.ts` enforces this.
- **Test files no longer share approval-store state.** A new Vitest setup file clears the per-pool test approval store before every test file (before the file is imported) and after it. With `KYBERION_TEST_LEAK_STRICT=1`, a test file that leaves approval records behind now fails, unless it is listed in `tests/fixtures/approval-store-leftover-baseline.json`. That list only shrinks: a test caps its size, and the guard prints a note when a listed file left nothing behind.
- **Concurrent Vitest runs in one checkout no longer wipe each other's approval records.** The test approval store is now `active/shared/runtime/vitest-approvals/run-<id>/pool-<n>/`, where `<id>` (`KYBERION_VITEST_RUN_ID`) is set per run by `vitest.config.mts`. Each run removes its own directory when it ends.
