- **`pnpm kyberion browser control` — interactive, session-leased browser control over the Chrome extension bridge** (Claude-for-Chrome style). A control session (`BCS-*`) is minted only after an operator approval and binds one canonical origin for up to 60 minutes. Low-risk steps (`open_tab`, `navigate`, `snapshot`, `click_ref`, `fill_ref`, `select_ref`, `press_ref`, `wait_for_ref`, `extract_text_ref`, `list_tabs`, `select_tab`) execute under that lease; high-risk ops (`submit_form`, `credential_submit`, `settings_change`, `delete`, `purchase`, `upload_file`, `download_file`) still require a per-step approval, resumed with `browser control resume <approval_id>` after `pnpm kyberion approvals --approve <id>`.
- **New mailbox kind `control_step`** in `browser-bridge-request.v1`: a schema-bounded step (`session_id` + `lease_id` + `origin` + fixed op vocabulary — never arbitrary JavaScript) that the extension executes automatically against the session-bound tab, re-checking the origin on every step so a session can never follow a navigation out of its approved origin. `extract_text_ref` steps with `secret_name` return their text through a secrets side-channel file instead of the persisted response, so tokens (e.g. Slack `xapp-`/`xoxb-`) never land in the mailbox record, the journal, or the audit chain.
- New modules: `libs/shared-vision/src/browser-control-sessions.ts` (session lease store, step-hash admission, journal) and `browser-control-service.ts` (approval orchestration, pending-step resume). Session state lives under `active/shared/runtime/browser-control/` — operator-local, per-checkout like the rest of the bridge.
