---
category: Removed
---

- **`pnpm kyberion mesh deliver` and the `mesh-delivery` pipeline** — removed together with the Mesh message broker, its delivery driver and the pipeline op `core:run_mesh_delivery`. Nothing ever enqueued a Mesh delivery, so the driver had no work and the `mesh-delivery-5min` schedule was already disabled. Peer collaboration requests are unchanged: they arrive as conversation handoffs and wait for `pnpm kyberion peer collaboration` on the recipient. `pnpm kyberion mesh-hub inspect` and the doctor "Mesh delivery" line still read delivery rows an older runtime root may hold. `KYBERION_MESH_PEER_ID` and `KYBERION_MESH_SHARED_SECRET` are no longer read and left the env registry. No action is needed unless you scheduled the pipeline yourself; remove that schedule.
- **`mesh-delivery-5min` schedule** — the schedule shipped disabled and ran only on hosts that listed it in `KYBERION_CHRONOS_SCHEDULES`. It no longer exists; remove the id from that variable.
- **`core:run_mesh_delivery`** — a pipeline step that uses this op now fails as an unknown op. Remove the step.
- **Mesh dead-letter inspection reads one tenant's file** — `pnpm kyberion mesh-hub inspect` and the doctor line read only `tenants/<tenant>/dead-letter.jsonl` for the requested tenant. The retired reader scanned every tenant's file and then filtered by tenant scope, so a row stored under another tenant's directory is no longer reported.
- **`@agent/core` API removed with the broker** — `createMeshMessageBroker`, `MeshMessageBroker`, `MeshHubCommandLoop`, `acceptMeshRequest`, `enqueueMeshDelivery`, `claimDueMeshDeliveries`, `acknowledgeMeshDelivery`, `rejectMeshDelivery`, `retryMeshDelivery`, `expireMeshDeliveries`, `listMeshDeliveries`, `listMeshDeadLetters`, `clearMeshMessageBrokerNamespace`, `runMeshDeliveryPass`, `formatMeshDeliveryPassReport` and their option and result types; `buildWorkCoordinationPeerCommandEnvelope` and the `WorkCoordinationPeerCommand*` types; `MeshHubDispatchInput`; and the adapter methods `MeshHubPeerMessagingAdapter.dispatchToPeer` / `createResponder`. Five subpath exports are gone: `./mesh-delivery-driver`, `./mesh/mesh-delivery-driver`, `./mesh/mesh-message-broker`, `./work-coordination-peer`, `./workforce/work-coordination-peer`. `MeshDeadLetterRecord` is still exported.
- **Peer coordination responder** — `createWorkCoordinationPeerResponder` / `processWorkCoordinationPeerCommand` are no longer exported from `@agent/core`. No listener installed them. A peer asks for work through a typed peer task (`pnpm kyberion peer task`), which the recipient accepts locally.
