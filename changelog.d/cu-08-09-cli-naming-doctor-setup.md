- CU-08: package scripts follow one naming rule — `noun` or `noun:verb` for operator commands, verb-first only for the toolchain families (`build`, `test`, `lint`, `check`, `generate`, `verify`, ...). Renamed: `dev` → `verify`, `chronos` → `scheduler`, `inventory` → `work:inventory`, `customer:*` → `stance:*`, `onboard` → `onboarding`, `ingest` → `knowledge:ingest`, `knowledge-feedback` → `knowledge:feedback`, `services:setup` → `service:setup`, `managed-env` → `provider-cli:setup`, `agy:sdk:setup` → `agy:sdk-setup`, `report:i18n-coverage` → `i18n:report`, `migrate:physical-namespaces` → `namespace:migrate-physical`, `migrate:peer-tenant-runtime` → `peer:migrate-tenant-runtime`, `watch:tenant-drift` → `tenant:watch-drift`, `export:validation-bundle` → `validation-bundle:export`, `dev:watch` → `test:watch`. Every old name still works and prints one deprecation line; `kyberion <old noun> <old verb>` (e.g. `kyberion customer create`, `kyberion chronos install`) routes to the new command with one warning. `check_cli_manifest` now rejects new verb-first or three-segment script names.
- CU-09: `pnpm kyberion doctor --scope env|service|voice|meeting|app|setup` and `pnpm kyberion setup <onboarding|context|reasoning|env|services|tools|provider-cli|agy-sdk|voice|config>` give diagnostics and setup one entry each; every scope delegates to the existing command, bare `doctor` is unchanged, and `kyberion --help` / bare `kyberion setup` list the scopes (en + ja).
