category: Fixed
---

- A runtime store's size no longer makes a read or an append fail. New size-independent JSONL readers (`libs/core/jsonl-read.ts`: last line, backward scan, forward stream) and shared write-time retention (`libs/core/append-only-store.ts`: rotate, compact by key, time window) that the janitor now also uses; the janitor can compact stores larger than 100 MB.
- The trigger delivery journal has no 5 MB append cap or 8 MB read window: dedupe scans backward over the 7-day window. Its inline rotation moves only the dropped records to the segment and runs only when it frees at least half the journal (and a quarter of its 4 MB threshold), so a large dedupe window is not rewritten on every append. The storage janitor never rotates the live journal (catalog `self_managed`), so the dedupe window and in-flight claims survive; it only expires rotated segments.
- Ledger and audit-chain appends no longer re-read the whole file; an unreadable newest audit day, or one holding only junk lines, refuses the append instead of silently forking the chain from an older file. A day file deleted or rotated mid-read counts as absent, and a caller whose own access scope cannot read the chain tail no longer gets a throw from `record()` (the write is skipped and logged). Verification streams.
- The stimuli journal drops its 5 MB / 11 MB caps; mesh presence compacts at write time to the latest heartbeat per peer, with no archive and an audit record per compaction; mesh, dot action ledger and mission queue readers stream without a cap; the mission queue drops terminal rows older than 14 days.
