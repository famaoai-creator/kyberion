category: Changed
---

- Organization learning candidates and process-improvement proposals are now rows on the one memory candidate queue (`kind: organization_learning` / `process_improvement`, with an `origin` naming the deciding facade). `pnpm organization learning enqueue|transition` and `pnpm mission improvements --approve|--reject|--apply` create and decide those rows; the generic promotion (`promoteMemoryCandidateToKnowledge`, `memory-promote-pending`, the Concierge bulk promote) refuses them with `MEMORY_PROMOTION_OWNED`, so each learning has one promotion path. The old per-organization learning files and the shared `coordination/process-improvements/queue.jsonl` are read-only. For one release, `pnpm organization learning migrate --dry-run|--apply` and `pnpm mission improvements --migrate [--write]` import pending items with the scope their record (or mission state) declares, and list items whose scope cannot be determined under `unresolved` instead of guessing. Applied process-improvement work orders are written to the proposal's own tier/tenant artifact partition instead of a shared directory.
- `wisdom:distill` builds its summary from public memory candidates only (no longer from distill candidate records across tenants), and the memory-distillation pipeline nominates that summary as a public candidate.
- Runtime hints live in one hint store partitioned by capture scope (`active/shared/runtime/hints/<tier>/<tenant|shared>/`, `libs/core/knowledge/hint-store.ts`). `HINTS.md` files are generated from it: the product view from public hints only, a tenant view from that tenant's hints only — personal or tenantless confidential promoted hints no longer appear in the product `HINTS.md`. Human-rejection lessons are stored in the rejected mission's scope, and a worker brief only shows lessons from its own mission's scope. The old `active/shared/runtime/feedback-loop/hints/` directory is read-only for one release.
- `wisdom-policy.json` is renamed `distill-policy.json` (schema `distill-policy.schema.json`); the old path is read for one release when the new one is absent. `KYBERION_WISDOM_LLM_PROFILE` is renamed `KYBERION_DISTILL_LLM_PROFILE`; the old name is still accepted for one release with a deprecation warning. A volatile sidecar nominated as a memory candidate now records `status: nominated`; the old `promoted` value is read as `nominated`.
