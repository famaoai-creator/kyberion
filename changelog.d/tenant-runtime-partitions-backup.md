- **Tenant backup, restore and offboarding cover every tenant runtime partition** — one registry walk (`TENANT_RUNTIME_PARTITION_ROOTS`) now drives all three. A tenant backup includes the tenant's hybrid-ledger, approval-store, usage and execution-metrics partitions and the partitioned state roots, and its manifest lists them (`tenant_runtime_partitions`) with the audit chain key id (`chain_key_id`), never the key. Tenant offboarding also exports and soft-deletes the pipeline-library-run, autonomy-learning, external-operation, hearing, discussion-create-request and standing-grant partitions (new target kind `tenant_runtime_state`).
- **Restore refuses silent ledger rollbacks** — a restore fails before extraction (`[BACKUP_RESTORE_APPEND_ONLY_CONFLICT]`) when the target already holds an append-only partition the archive carries. Torn last lines of restored ledgers are trimmed, restored tenant-ledger chains are verified when the target holds the same chain key (otherwise the output reports `deferred_key_mismatch`; set `KYBERION_AUDIT_CHAIN_KEY` to the source key and run `pnpm audit:verify`), and restored customer decision invites and standing grants are quarantined under `<partition>/.restore-quarantine/` so revoked state cannot come back. Upgrade note: new tenant backups include these partitions; restoring onto a live tenant that already has ledgers now refuses, so restore into an empty target and reconcile there.
- **Unplaceable mission ids no longer leak payloads into the system ledger** — a record whose mission id no process can place (and that names no tenant) keeps its raw `mission_id` and a `payload_digest` in the system ledger, with `payload_withheld: 'mission_unplaceable'`; the payload is not written. Rows written before this change are not rewritten. Chronos runtime remediation records now name the mission's tenant and carry only allow-listed lease metadata, and the secret actuator records `mission_id: 'None'` when its ephemeral mission could not be created.
