- **Execution Persona bundles become base Authority Roles (S4 slice 4)** — the path permissions of the `sovereign`, `ecosystem_architect`, `worker` and `analyst` personas moved verbatim from security-policy.json `persona_permissions` to registry cards `knowledge/product/governance/authority-roles/base_<persona>.json` (`"assignable": false`; `pnpm kyberion sync authority-roles` projects them into `authority_role_permissions`). The tier guard adds the base role a principal's persona names (`libs/core/foundation/base-authority-role.ts`); decisions are unchanged (`libs/core/testing/base-authority-role-equivalence.test.ts`, fixture `tests/fixtures/base-authority-role-equivalence.json`: 54 principals × 215 paths × read/write/mkdir, plus the resolved persona and authorities). A base role is never a principal's own role: `withExecutionContext('base_…')` is refused (`[ROLE_ASSUMPTION_DENIED]`) and a process running as the name through `MISSION_ROLE` / `SYSTEM_ROLE` resolves no record for it. An installation catalog without base roles is read from its `persona_permissions` for one release (schema keeps the field as optional, deprecated). Declared store grants name `baseRole: 'base_worker'` instead of `persona: 'worker'`. `KYBERION_PERSONA`, the `Persona` type and its agent-id uses are unchanged in this slice.
