category: Fixed

- **Reasoning egress posture is declared, not implied.** A confidential or personal reasoning payload scope now has to name its `training_use`. Before, a missing value silently meant `local_only`, so tenant drafting (customer decision drafts, roster proposals, advisory panels, mission background review, visual review, worker compaction summaries, confidential pipeline runs) was refused by every external backend, claude-cli included. Tenant working material now declares `no_training`, so it reaches an external backend only when the tenant holds a `training_use: 'none'` attestation for that provider. Personal material declares `local_only` explicitly. To enable a tenant, run `pnpm onboarding llm attest --tenant <slug> --provider <id> --training-use none --request-approval`.
- **Egress denials are reported as egress denials.** A `local_only` denial now says why, what to do next and what it saw. The roster proposer and advisory panel return `egress_denied` with the next step instead of `backend_unavailable`. The customer-decision draft still falls back to organization defaults, but it now returns `egress_denied` with a separate note.
- **Public material may be used for training.** A public reasoning scope, OCR request or knowledge context that declares no `training_use` now defaults to `training_eligible` instead of `local_only`, so public work reaches external backends without an explicit declaration. An explicit `local_only` is still honoured, and confidential and personal defaults are unchanged.
