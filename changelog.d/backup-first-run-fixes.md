- **Keychain secrets readable without a prompt** — `pnpm kyberion secret introduce` (and the encryption-master creator) now write macOS Keychain items with an access list that trusts `/usr/bin/security`, the binary Kyberion reads them with. Before, only the short-lived Swift helper was trusted, so launchd jobs such as `backup-daily` failed with `BACKUP_PASSPHRASE_MISSING`. Rewriting an entry deletes it with `security` and adds it again with the new ACL. Entries written before this fix keep the old ACL: run `secret introduce` once more to rewrite them.
- **Full backups no longer stop on guarded credential paths** — `pnpm kyberion backup` (scope all) failed with `[SENSITIVE_PATH_DENIED]` on `vault/secrets`. It now leaves `vault/secrets` out (it only names keychain entries; the secrets live in the OS keychain), along with every other guarded credential root except connection documents. `knowledge/personal/connections` is still backed up: the backup's file walk reads it through a narrow admission (read-only, those roots only, only into an encrypted archive; an unencrypted backup that covers it is refused with `[BACKUP_CREDENTIAL_READ_REQUIRES_ENCRYPTION]`), and the manifest records the roots read and their file counts under `credential_reads`, never contents. Restore extracts them back with tar as before. Every other caller is still denied.
