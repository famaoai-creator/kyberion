- **Tenant approvals are stored in the tenant's own partition** — an approval request whose scope names a tenant is now stored under `active/shared/runtime/tenant-approvals/<personal|confidential>/<tenant>/<channel>/` (request record, passkey challenges and the channel's `approvals.jsonl` event log) instead of the shared approval tree. A public tenant record goes in the confidential partition. Reads and writes use the tenant-bound `tenant_approval_store` role, so a process bound to one tenant cannot find or decide another tenant's approvals. Untenanted requests (Slack, plugins, operator), and activation requests for a tenant that is not yet active, stay in `active/shared/coordination/channels/<channel>/approvals/`. Every caller still addresses a request by `(storageChannel, id)`. The approval store hygiene sweeps (expired passkey challenges, fixture purge), the learning-signal rejection reader and mission flow evidence also cover the partitions. Tenant offboarding exports and removes them (target kind `tenant_approvals`).
- **Upgrade**: tenant requests written before this change stay readable and decidable where they are. To move them, run `node dist/scripts/approval_store_hygiene.js --migrate-tenant-partitions` (or `pnpm kyberion approvals hygiene --migrate-tenant-partitions`) from an unbound operator shell. This is a dry run that lists them. Then add `--apply` to move each record under its record lock. Each move writes and reads back the partition copy, removes the system copy and adds an audit-chain entry. The move can be run again safely. It refuses a record whose partition copy has different content (`[APPROVAL_MIGRATION_CONFLICT]`). Old lines in the system `approvals.jsonl` stay as history. The regular hygiene report shows how many records are still to move.
