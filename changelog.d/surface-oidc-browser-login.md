- **OIDC browser login for all five surfaces** — remote (non-loopback) browsers that open concierge, chronos-mirror-v2, operator-surface, presence-studio or computer-surface without a credential are now redirected to a shared sign-in screen instead of seeing a raw `{"error":"Unauthorized."}`. Generic OIDC Authorization Code + PKCE (Google and Microsoft Entra verified against their discovery documents); the session is a signed HttpOnly `kyberion_session` cookie that carries no authority — the `browser-session` authn provider re-derives the member scope on every request, and an IdP account that is not bound to an active member never gets a session. Loopback behaviour, bearer-token access and 401 JSON for API calls are unchanged. Enable with `KYBERION_OIDC_ISSUER`, `KYBERION_OIDC_CLIENT_ID`, `KYBERION_OIDC_CLIENT_SECRET` and `KYBERION_SESSION_SECRET` (plus `KYBERION_OIDC_PUBLIC_BASE_URL[S]` off loopback); the Google and Microsoft sign-in hosts are allowed in `egress-policy.json` by default (add other IdP hosts there). Signing in from the same machine works too (`http://localhost:<port>`, no public base URL needed) even where the Next.js surfaces cannot prove a loopback peer. See [SURFACE_OIDC_LOGIN_OPERATIONS](docs/developer/SURFACE_OIDC_LOGIN_OPERATIONS.ja.md).
- **Bind an SSO identity to a member** — `PATCH /api/members/<id>` accepts `external_identity` / `external_identity_remove` (owner on every tenant of the member; 409 if the identity belongs to another member), and the concierge settings members list exposes it.
- **operator-surface now requires a session off loopback** — it previously had no authentication at all while binding all interfaces. Loopback use is unchanged.
