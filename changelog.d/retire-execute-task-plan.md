---
category: Removed
---

- **`orchestrator:execute_task_plan` retired** — the op, its `wisdom:execute_task_plan` alias, the `execute-task-plan` pipeline template, the orchestrator task-plan coordinator and the deprecated core `executeTaskPlan` / task-plan coordinator seam are removed (wisdom-actuator 2.0.0). Task plans now run through `orchestrator:task_plan_to_next_tasks`, which writes the mission board (`NEXT_TASKS.json`), followed by normal mission dispatch (`pnpm mission dispatch-workitems <MISSION_ID>`), so every task runs under a claimed WorkItem. A pipeline that still calls the op fails with `[UNKNOWN_OP]` and an error that names this replacement. `faas-add-api` (3.0.0) now writes the board instead of executing the plan. Because `task_plan_to_next_tasks` replaces the board, it now refuses with `[TASK_PLAN_BOARD_CONFLICT]` when the board holds tasks it did not produce (for example a workflow template's default tasks) instead of dropping them.
- **Agent delegations without a WorkItem run read-only** — an agent execution port task without `work_item_id` (for example `agent:delegate` without one) starts the provider read-only: `claude` with only read and search tools available, write, shell and subagent tools denied, no MCP server and no user or project settings, `codex` in an isolated read-only, no-network app-server. Any other provider, including `agy`, and the pane backend refuse with `[TOOL_READ_ONLY_UNSUPPORTED]`. Work that writes must pass `work_item_id`. The `agent_delegation_unclaimed` audit record now includes `tool_access`.
