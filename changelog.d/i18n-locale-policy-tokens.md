- **Chat replies follow the user's language; locale branches use shared helpers; more hard-coded Japanese moved to the vocabulary (IT-02 rest, IT-03)** — slack / telegram / discord / imessage / chronos / voice replies now derive their locale per turn: an explicit request locale wins, otherwise the language of the incoming message (`detectTextLocale`, which ignores ids, digits, acronyms and one-word acks such as "Yes" / "OK" / "Thanks"), otherwise the locale stored for the turn's scope, otherwise `resolveLocale()` (operator identity, `KYBERION_LOCALE`, `LANG`, the process locale, then the catalog default, which now warns once). The chat bridges no longer pass the operator locale as an explicit turn locale, so the orchestrator's derivation decides; the turn locale is scoped with `runWithReplyLocale` (it never leaks into the caller) and is in effect before the background review fork starts. It is honored by `resolveLocale()` right after an explicit argument or surface preference, so every `t()` reply builder follows it without a locale parameter; the three duplicated kana regexes in the surface router, orchestrator and channel adapter now share the detector. `libs/core/locale-normalize.ts` gains browser-safe `localeToBcp47`, `pickByLocale`, `coerceLocale` and `localeUsesWordSpaces`, replacing ad-hoc `locale === 'ja' ? ... : ...` branches and hard-coded `ja-JP` / `en-US` speech and `Intl` tags across core, voice-hub, chronos, concierge and operator surfaces (defaults that denote the operator's language now derive from the locale). Mission hygiene / retrospective / maintenance notices, project bootstrap work items, lead-score reasons, clarification formatting, contextual question reasons, automation blueprint prompts, the orchestrator brief questions and follow-ups, voice repair progress, and the chronos page notices moved to vocabulary keys (en + ja). The i18n baseline fell from 188 to 52 violations.
