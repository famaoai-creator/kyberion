category: Security

- **Terminal attestation for human-only CLI decisions** — `pnpm kyberion approvals --approve/--reject` on a human-only request now always runs the terminal challenge. It shows the request, target, tenant, effect, the presented digest and the expiry, and the operator types back a random 6-character code that expires after 60 seconds. It refuses with `[APPROVAL_HUMAN_PROOF_REQUIRED]` when stdin/stdout are not a TTY, inside an agent session, or when the command runs under a provider CLI process. Provider CLIs are matched against the full command lines of every parent process up to pid 1, including CLIs wrapped by node, bun or python. CLIs that run as `node …/cli.js` are recognised by install path through the new optional `cli.install_path_markers` in the reasoning-provider registry (e.g. `/@anthropic-ai/claude-code/`). A successful decision is recorded as `terminal_attested` (A2). The audit trail records the OS user, the tty and the parent-process lineage.
- **Surfaces record the proof they actually have** — Concierge, Chronos and Presence Studio record `surface_session` only when a member was resolved from a verified session. The localadmin bearer, an agent principal and Chronos' sovereign fallback (no resolved member) are recorded as `local_admin_token`, which a human-only decision refuses. The credential-free loopback Presence Studio inbox is recorded as `manual`. Chat bridges stay `channel_identity`.
- **Decisions are bound to what the decider was shown** — surfaces compute a presented digest when they render a request and send it back with the decision. The digest covers everything Chronos, Concierge, Presence Studio, Slack, chat cards and the CLI display: kind, channel, title, summary, details, severity, source text, requested and expiry times, target, tenant, organization, requester (with display name and the full requester context), the full justification and risk profile, track, the full work loop (intent, execution shape, outcomes, team, authority, project, tenant), the workflow shape (mode, required roles, stages — not the approvals collected so far), what a steering request will do, the decision-card body, and the effect binding. Chronos' approvals workspace now reads the tenant from the request scope first and labels a tenant taken from mission state as not on the request. Chat cards embed a 12-character digest in the button token (`appr:<id>:approve:<digest>`), which only the chat callback path accepts; the store and HTTP routes require the full digest, which Slack embeds in the button value. The approval store recomputes the digest from the stored request and refuses a mismatch with `[POLICY_VIOLATION]`; chat surfaces reply that the request changed since it was shown. A human-only decision without a digest is accepted and audited (`presented_digest_missing`) under the default `KYBERION_APPROVAL_ASSURANCE=warn`, and refused under `enforce`.
- **The approval store refuses human-only decisions from agent processes** — `decideApprovalRequest` refuses a human-only decision with `[APPROVAL_HUMAN_PROOF_REQUIRED]` when the deciding process is an agent session, or when the authenticated principal passed by an HTTP decision route is an agent. The only exemption is a human-decision surface server launched by the surface runtime (its `SYSTEM_ROLE`), and only when no agent principal is involved. In warn mode, a decision with an assurance shortfall no longer seeds the session approval cache.
- **Refusals point to a path that will pass under enforce** — human-only refusals now point to a signed-in Concierge or Chronos session or the terminal challenge, no longer to Presence Studio (recorded as `manual`, A1).
