category: Changed
---

- The operations console (formerly the Chronos surface) now runs inside Concierge: pages at `/ops` (`/ops?section=…`, `/ops/discussion`) and the API at `/api/ops/*`, inside the normal Concierge rail and header. The front-desk rail's deliverables, knowledge, discussion, operations, surface-control and diagnostics entries open these Concierge pages. Every `/api/ops` route resolves the Concierge viewer; the Chronos-specific guard and loopback auto-admin are gone.
- Chronos (port 3000) is now a compatibility app: `/api/healthz` stays local, `/api/<path>` answers `308` to Concierge `/api/ops/<path>` and every other path answers `308` to Concierge `/ops` (query string kept), so old bookmarks keep working.
- Workspace autonomy (pause / resume / activate) and the schedule quick actions are dispatched to governed workers (`scripts/dot_lifecycle_worker.ts` under `SYSTEM_ROLE=dot_lifecycle_worker`, `scripts/run_generation_schedule.ts` under `SYSTEM_ROLE=generation_schedule`) and audited as `governed_worker_dispatch`. Concierge itself never assumes the lifecycle or scheduler writer roles. `pnpm kyberion dot pause|activate` accepts `--expect-status`, `--expect-admission-hash` and `--expect-scope-json` and refuses the transition when the charter changed.
- Migration note: operations writes now pass the Concierge mutation gate. A script that POSTs with a registered (member) localadmin token and no `Origin` header, which Chronos accepted, now gets `403`. Send the request with an `Origin` equal to the Concierge origin, or authenticate with the configured `KYBERION_LOCALADMIN_TOKEN` / `KYBERION_API_TOKEN`. Credential-less loopback requests are no longer an automatic localadmin either: they are admitted only while first-run bootstrap is open or with `KYBERION_CONCIERGE_ALLOW_ANONYMOUS_LOOPBACK`.
