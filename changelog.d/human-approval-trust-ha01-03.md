category: Security

- **Agents can no longer settle human-only approvals** — MCP `kyberion.approval.decide` and the approval-actuator `decide` op refuse any request with `accountability.finalDecision: 'human_only'` (approve or reject) with `[APPROVAL_HUMAN_PROOF_REQUIRED]`. Other decisions through these paths are still accepted but recorded as `decidedByType: 'ai_agent'`, `authenticated: false`, regardless of what the caller claims. `pnpm kyberion approvals --approve/--reject` run inside an agent session refuses human-only requests the same way, whether or not separation of duties is on. Enforced immediately, with no warn period.
- **Human-only decisions declare their proof strength** — every human-only request now carries `accountability.min_assurance` (A2 by default, A3 for dual-key secret operations), and each `authMethod` provides a fixed level: `channel_identity` / `manual` / `local_admin_token` A1, `surface_session` / `terminal_attested` / `totp` A2, `passkey` A3. A decision with no or an unknown `authMethod`, or with `local_token` / `local_admin_token`, is always rejected. A decision below the required level is governed by the new `KYBERION_APPROVAL_ASSURANCE` (`warn` by default: accepted, recorded as `assuranceShortfall` on the record and `assurance_shortfall` in the event log, audited and sent to the operator as an ops alert; `enforce`: rejected). Slack, Telegram, Discord and iMessage decisions are now recorded as `channel_identity`; presence text decisions as `manual`.
- **One agent-session detector** — `detectAgentExecutionContext()` (`@agent/core/agent-execution-context`) replaces the separate provider-CLI checks in the CLI approval principal, the Claude agent bundle, the host image bridges and `generate_avatar`. agy sessions (`AGY_CLI` / `ANTIGRAVITY_CLI`) are now detected as agent sessions too.
