- **Keep scratch builders before tmp cleanup** — `pnpm scratch:promote --from <dir> --name <tool> (--tenant <slug> | --public)` copies the authored files of a scratch directory into `knowledge/confidential/<slug>/tools/<tool>/` (or `knowledge/public/tools/<tool>/`) with a `TOOL.json` manifest (provenance, sha256 per file, entry points, run command, follow-up). `pnpm pipeline:promote --tenant <slug>` lands a pipeline in the tenant catalog (`knowledge/confidential/<slug>/pipelines/` + its README) and never touches the public `pipelines/README.md`. Every tenant promotion (dry run and `--force` included) prints and returns `next_steps`: `pnpm kyberion project-trust request <path>`, human approval, then `pnpm pipeline --input <path> --project-trust-approval <id>`; the tenant README's Run column uses the same governed command. Without `--tenant`, both commands refuse sources in a personal/confidential tier or a tenant-partitioned path, and unpartitioned scratch too unless `--source-is-public` confirms the content is public. Tier and tenant segments are matched case-insensitively. Tenant writes go through the tenant-bound `asset_promoter` role and public tool writes through `public_tool_promoter`.
- **Tenant promotions are ledgered assets** — `scratch:promote --tenant` and `pipeline:promote --tenant` append a record to the tenant asset ledger (`_ledger/assets.jsonl`): source path, sha256 of the written `TOOL.json` or pipeline file, `ingested_by`, `visible_to: [<slug>]`. A `--force` re-promotion with new content supersedes it (version+1); identical content adds nothing. The ref comes back as `asset`. Dry runs and public promotions record nothing. `asset_promoter` gains write access to its own tenant's `_ledger/` only.
- **Tmp sweep grace for unpromoted code** — the retention catalog's `code_grace_days` (tmp entry, default 2) keeps job directories that hold authored code or ADF past the tmp TTL until they are promoted. The janitor warns with the exact promote command and lists them in `active/shared/runtime/system/scratch-promotion-candidates.json`; tier-partitioned jobs appear there and in the warning only as a salted opaque id + tier, and are promoted with `pnpm scratch:promote --candidate <id> --tenant <slug> --name <tool>` (resolved only inside that tenant's own partitions). Promote hints in pipeline runs, peer collaboration and work-inventory plans now name `--tenant`.
- **Baseline visibility** — the session baseline report carries a warn-only `warnings.scratch_promotion_candidates` line while scratch dirs sit in their code grace window (never a status input).
