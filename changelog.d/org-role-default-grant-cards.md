- **Org Role default grants live on the Org Role card** (concept model v2 D6) — each role directory in `knowledge/product/roles/` now has a card `role.json` (schema `org-role-card.schema.json`) declaring its `role_class` and `default_grant` (`authority_role`, `base_role`, `execution_mode`). The card only points at registry entries and grants nothing itself. `knowledge/product/governance/role-authority-map.json` is now generated from the cards by `pnpm kyberion sync org-role-grants`; the new `org-role-grants` gate fails on drift, or when a card names an Authority Role the registry does not have or an unknown base role. Edit the card and regenerate instead of editing the map. `pnpm organization role create` / `promote` write the card and the map together; `promote` now keeps a role's existing class instead of moving it to `context_roles`. No reader result changed: the regenerated map matches the old one except for its description (`scripts/org-role-default-grant-equivalence.test.ts`, fixture `tests/fixtures/org-role-default-grant-equivalence.json`). `role-write-access.json` is unchanged, because it is keyed by Authority Role, not Org Role.
