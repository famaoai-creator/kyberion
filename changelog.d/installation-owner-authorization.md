- **Installation settings are authorized by the installation owner, not by loopback** — Concierge operator services, the owner's profile and avatar, and personal onboarding authority now go through one decision (`libs/core/surface/installation-owner-access.ts`). The signed-in owner member can read these settings from any device. A change needs a trusted loopback peer, or a passkey step-up from the same session within the last 5 minutes (`purpose: installation` on `/api/me/passkeys`). Other members get a stable `installation_owner_required` code, and the settings panels show a read-only notice or a "confirm with passkey" step instead of a 403. Credential-less loopback stops being `localadmin` once an owner is bound (it gets 401 and browsers go to `/login`). The default-off `KYBERION_CONCIERGE_ALLOW_ANONYMOUS_LOOPBACK=1` keeps headless automation working, with a warning. The Concierge health probe moves to the public, data-free `/api/healthz`. See `knowledge/product/governance/installation-owner-authorization.md`.
- **Migration** — `KYBERION_LOCALADMIN_TOKEN`, other env tokens and agent principals now get `installation_owner_required` on installation-scope settings, and so does a readonly credential bound to `owner`. Previously a credential-less loopback request reached these settings. Use a registry token bound to the `owner` member with role `localadmin` (for example the first-run token), or set the `KYBERION_CONCIERGE_ALLOW_ANONYMOUS_LOOPBACK=1` escape hatch for local automation.
- **Bootstrap closes for good** — bootstrap closes once the `owner` member holds any credential (whatever its memberships), and the closure is recorded and permanent: `bootstrap_closed_at` is written to the first-run document. The owner's first passkey can be registered only from the machine itself. If an owner is locked out, use the recovery in `knowledge/product/governance/installation-owner-authorization.md` (`pnpm organization member link-identity owner …`).
