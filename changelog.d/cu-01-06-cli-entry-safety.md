- **Safer, self-describing `kyberion` CLI (CU-01〜06)** — `--help` / `-h` never runs a side effect: `pr create`, `secrets encrypt`, `manifests sign`, `onboard`, the tenant migrations, `pipeline promote`, `knowledge scope-reconcile`, `resolve generated`, and `changelog assemble` print usage through a shared guard (`scripts/lib/cli-guard.ts`) and reject unknown flags (exit 2); for every other script-backed command without its own guarded help, the router answers `--help` from the registry instead of running it (`native_help` in `cli-commands.json`). Interactive and long-running commands (`tui`, `office`, `onboard`, pad servers, `mcp server`, `telegram bridge`, daemons, `build`/`check`/`test`, …) are marked `interactive` / `long_running` and run on the operator terminal with no 2-minute timeout. Every registry entry now has an en/ja `description` and a `group`; `kyberion --help` and `kyberion help` share one grouped renderer (start / inspect / operate; dev with `--all`; `help --detail` keeps the per-verb syntax), with a caution under `pr create`. Unknown commands get a did-you-mean hint. The registry check rejects a script-backed command shadowed by a governed one unless declared `same_target_as`; `pnpm intent` is renamed `pnpm intent:trace` (`kyberion intent trace`) and the old name still works with a deprecation notice. Package scripts that run `dist/` now go through `scripts/run_built.mjs`, which prints "run `pnpm build` first" instead of a raw `ERR_MODULE_NOT_FOUND`.
