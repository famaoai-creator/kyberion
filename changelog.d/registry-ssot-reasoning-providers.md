category: Changed

- **Reasoning provider registry is the single source of truth (RS-01〜03)** — `knowledge/product/governance/reasoning-providers/*.json` now declares transport, data egress, adapter, capability profile, CLI binary / probe / sandbox / install metadata, discovery membership, model env keys, egress endpoint and provider id, setup hints and runtime notes. The capability profile table, environment probes, conformance and sandbox matrices, CLI-discovery set, managed provider CLIs, model env map, egress endpoint / provider-id maps, route-doctor probes and remediation, API / OpenAI-compatible bundle builders, intent-compiler provider mapping and pane-agent model flag are all derived from it. A provider on an existing adapter is accepted end-to-end by adding its JSON; an incomplete descriptor fails closed with `[REASONING_PROVIDER_REGISTRY_INVALID] <mode>: <reason>`, and an unknown intent-compiler provider raises `[INTENT_COMPILER_PROVIDER_UNSUPPORTED]` instead of silently becoming codex. Copilot is now probed as `gh copilot -- --help` everywhere (conformance previously probed a nonexistent `copilot` binary).
- **Runtime model ids come from `provider-config.json`** — new roles `codex-fast`, `grok-default`, `gemini-image`, `ollama-vision` plus `runtime_endpoints.ollama`; the Gemini default is unified on `gemini-3.8-flash` (lifecycle and API backend). `GEMINI_API_DEFAULT_MODEL`, `GROK_API_DEFAULT_MODEL`, `DEFAULT_GEMINI_IMAGE_MODEL` and `MANAGED_PROVIDER_CLI_IDS` constants are replaced by `geminiApiDefaultModel()`, `grokDefaultModel()`, `defaultGeminiImageModel()` and `listManagedProviderCliIds()`.
