- **Tenant mission ledger events stay in the tenant's scope** — `ledger.record` now takes a record's scope from its mission's location (`active/missions/<tier>/<tenant|shared>/<id>`, or its archive dir; organization and project from the mission state) when the record omits it, so a confidential tenant mission's `MISSION_CREATE` / `MISSION_ACTIVATE` / `MISSION_DISTILL` / `MISSION_FINISH` and orchestration events are no longer recorded with tier `public` or scope `system`. The metadata entry of a tenant mission (and the detailed entry of an archived tenant mission's or a tenant record without a mission ledger) is written to that tenant's own hash-chained partition, `active/shared/runtime/tenant-ledger/<personal|confidential>/<tenant>/ledger.jsonl` (a public tenant record is stored in the confidential partition), as the new tenant-bound `tenant_ledger_store` role; the system ledger (`active/audit/system-ledger.jsonl`) no longer receives any tenant slug or tenant mission metadata. Untenanted (public / shared) missions keep today's behavior. A record whose tenant this process may not bind, whose mission state disagrees with its location, or whose mission is not resolvable by this process is skipped with a warn instead of throwing or falling back to the system ledger; a ledger whose last line cannot be parsed now refuses to append (`[LEDGER_TAIL_UNREADABLE]`) instead of restarting its hash chain. Existing system-ledger entries are not rewritten. `pnpm audit:verify`, `system:pulse_status` and mission `finish` verify the tenant partitions too (one chain per file; another tenant's partition is reported as withheld to a tenant-bound process), `loadForScope` reaches the partitions of the tenants a filter names under the reader's own tier-guard decision, and tenant offboarding exports and removes the tenant's partitions. If you read tenant mission events from the system ledger, read the tenant partition instead.
- **Autonomy learning sweep lock no longer overflows the file name** — the overrides-sweep lock id is a SHA-256 of the overrides file's path instead of the URL-encoded absolute path, which exceeded 255 bytes under long checkout roots (`ENAMETOOLONG`).
