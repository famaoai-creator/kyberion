- Tenant rename now moves `customer/{slug}/` — which holds the tenant's audit mirror — under the audit chain lock, and marks the move in the chain with a `tenant.audit_mirror_moved` entry. `audit mirror-reconcile` counts the old slug's earlier entries as the renamed mirror's, so a rename alone is no longer reported as drift. It follows a marker only by its own audit id, which the rename stores in the profile (`metadata.audit_mirror_move_ids`), and only when the profile's rename history holds that step (`metadata.previous_slugs`, which each rename now appends to; older profiles fall back to `tenant_id` and `metadata.previous_slug`). A marker recorded by anything else is never followed. A later tenant reusing the old slug, or an earlier owner of the new slug, keeps its own entries. The rename checks that both of its audit entries would be accepted before it moves anything, so a refused entry cannot leave a tenant half renamed.
- The storage janitor archives a master audit day file together with every tenant mirror's file for the same day, under the audit chain lock, all or nothing: if one file cannot move, the ones already moved are moved back (`RETENTION_ROLLED_BACK`) and the failure is reported in the janitor's errors, together with any file that could not be moved back. The mirrors are listed under the lock, so a concurrent rename cannot hide one. Archiving only the master used to leave mirror entries with no live master copy. A dry run lists the mirror files too. The trash, archive and retention-audit primitives moved to `storage-retention-expiry.ts` (still exported from `storage-janitor.ts`).
- A write denied by policy inside an audit-locked section now fails at once with its `[POLICY_BLOCKED]` reason. It used to wait out the 5-second lock on itself and report a lock timeout. The denial is still audited, right after the lock is released (`auditChain.recordDeferrable`). A plain `record()` inside the lock now fails immediately with `AUDIT_REENTRANT`. New `withAuditChainLock` and `auditChain.recordHeld` let a locked section record an entry at an exact point.
