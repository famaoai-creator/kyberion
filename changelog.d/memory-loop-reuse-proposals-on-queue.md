category: Changed
---

- The last four producers of proposed distill-candidate records now write rows on the one memory candidate queue, with their scope written at capture. Learning-intake plans (`pnpm kyberion learning prepare`) are `learning_intake` rows with the plan's own scope; `--queue` hands them to steward review as before, and the review and publication checks read the row. Service procedure candidates (`service_recording candidate`) are `service_procedure` rows with the recording's scope, and an owner-less personal candidate is refused (`MEMORY_SCOPE_REQUIRED`) instead of being saved unscoped. Mission-seed reuse proposals from Concierge are `mission_seed` rows with the started mission's tier and tenant (and its project when it belongs to that tenant), and are not captured for a non-public mission without a tenant. A completed browser-extension run is a personal learning of the local owner (not captured without one).
- Concierge decides service-procedure and mission-seed proposals (`decided_via: concierge`); other proposals show which command decides them and have no buttons. Old distill-candidate records are read-only history: Concierge no longer promotes or archives them (it answers 409 with the reason). For one release, `pnpm kyberion learning prepare --migrate [--dry-run]` imports pending ones with the scope the record declares and lists the rest as unresolved, never guessing a scope.
- Concierge (reuse-proposal panel) and Presence Studio (`/api/distill-candidates`) list queue-row proposals again, including background-review and execution-feedback proposals, filtered by the viewer resolved server-side (never personal rows), with the old records after them as history.
- `tests/distill-candidate-receipt-boundary.test.ts` has an empty `PENDING_MIGRATION` list; `memory-candidate` in the concept registry is no longer marked transitioning.
