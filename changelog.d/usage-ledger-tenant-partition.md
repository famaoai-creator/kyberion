- **Resource-usage ledger partitioned by tier and tenant** — `MetricsCollector.recordResourceUsage` no longer appends tenant or personal/confidential usage (mission ids, task ids, `tenant_slug`) to the repo-wide `work/metrics/resource-usage.jsonl`. A record whose scope carries a tenant or a non-public tier now lands in `active/shared/runtime/usage-ledger/<tier>/<tenant|shared>/resource-usage.jsonl`; untenanted public / unscoped usage stays in the system file. Callers are unchanged. Readers choose a partition: `loadResourceUsageHistory()` is system-only, `{ scope }` one owner's partition (mission retrospective, generation-cost dedup), `{ tenants }` a tenant cost report, `{ all: true }` the operator aggregate (cost report without a tenant filter, terminal HUD). `usage-ledger/{personal,confidential}/` are new `tenant_scope.protected_prefixes`, and tier-guard now applies the tenant check to reads of tenant-protected `active/shared/runtime/` paths, so a tenant-bound process can neither read nor write another tenant's partition. Pre-existing mixed rows in the system file stay readable as legacy, filtered by each row's own scope (no split migration). The new store has a retention-catalog entry and is sandboxed under Vitest. `resource-usage.schema.json` now declares `cause`, which every record carries.
