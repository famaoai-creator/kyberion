category: Added

- **`cursor-sdk` reasoning backend** — a new opt-in reasoning mode that calls Cursor through `@cursor/sdk` (`Agent.create` → `send` → `wait`) instead of spawning the `cursor-agent` CLI. It runs tool-less text reasoning (`tools: []`) in an empty scratch workspace with `settingSources: []` and a scratch conversation store, validates structured ops with the same prompt-enforced JSON + Zod path as `cursor-cli`, and records token usage. Authenticate with `pnpm kyberion secret introduce cursor API_KEY` (or `CURSOR_API_KEY`), then select it with `KYBERION_REASONING_BACKEND=cursor-sdk`; override the model with `KYBERION_CURSOR_SDK_MODEL` (default `composer-2.5`). It is not auto-selected — `CURSOR_API_KEY` still auto-selects `cursor-cli` — and it refuses tenant- and personal-bound executions (`[CREDENTIAL_NATIVE_UNSUPPORTED]`). Use `cursor-cli` for agentic, tool-using work.
- **`cursor-sdk` latency and reliability** — the system prompt is folded into the user message by default, because accounts without Cursor's native `systemPrompt` reject the run only after ~20s of SDK-internal retries (first call 27s → 8.6s, warm calls ~4s). Accounts that have the feature can opt in with `KYBERION_CURSOR_SDK_NATIVE_SYSTEM_PROMPT=1`. Structured ops get one repair round that feeds the validation failure back to the model, and an invalid-model error now lists the available ids and points at `KYBERION_CURSOR_SDK_MODEL`.
- **`cursor-cli` session continuity declaration** — the `cursor-cli` descriptor now declares `session_continuity: true`, which matches the backend (it keeps the `--resume` session on one instance and drops it on `resetSession()`). A live `follow_up` / `reset_continue` run measured both; `cursor-sdk` is covered by its own continued-conversation entry below.
- **`cursor-sdk` continued conversations** — `context_mode: 'fresh' | 'continue'` on a call opts in to one conversation held by the backend instance; calls without it stay stateless. Continued turns are serialized FIFO, the agent and scratch directories are released after an idle TTL (`KYBERION_CURSOR_SDK_SESSION_IDLE_TTL_MS`, default 15 minutes), and a failed turn, model change, `'fresh'` turn or `resetSession()` discards the conversation. The descriptor now declares `session_continuity: true`, confirmed by the live `follow_up` and `reset_continue` scenarios (continued turns ~1.8s vs ~4s fresh).
