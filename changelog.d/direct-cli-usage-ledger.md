- **Direct-CLI mission work shows up in usage accounting** — when `mission_controller record-evidence` or `review-task` completes a task it now appends one estimated entry (plus one per task the call completes by dependency cascade) (`status: estimated`, `source: direct_cli`, quantity/cost 0, token fields null — nothing fabricated) to the existing resource-usage ledger (`work/metrics/resource-usage.jsonl`), carrying mission/task scope, actor id and provider (new optional `--provider` flag, validated against the known provider ids — an unknown value is warned about and dropped — otherwise inferred from a provider-prefixed `--actor-id`); the mission tier/tenant is required, so a confidential mission without a tenant records nothing rather than being downgraded to public. The retrospective stats gain `tasks_completed` and `usage_unrecorded` (completed tasks but zero usage entries of any kind), and the rendered retrospective states plainly that such zeros mean "not recorded", not "free".
- **Metrics ledgers sandboxed under Vitest** — `path-resolver` now maps `work/metrics/` (execution-metrics and resource-usage ledgers written by the shared `metrics` collector) into the Vitest live sandbox via `VITEST_LIVE_REPO_SUBTREES`, and the leak guard watches `work/metrics`, so test runs no longer append to the developer's real metrics files.
