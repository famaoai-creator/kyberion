category: Changed

- **One operator identity for terminal approvals** — CLI and script approval requests (provider attestation, project trust, external hooks, secret introduction, mission scope-approve and reconcile-work, organization decisions, entity-governance cleanup, audit-mirror reconcile, third-party `pnpm plugin:install`, service recordings) and `pnpm kyberion approvals --approve` / `pnpm kyberion approve` now record the local owner member as `user:<member_id>` on both sides, with the onboarding name kept in `requestedByDisplayName` / `decidedByDisplayName`. The mission brief page records the same principal. A CLI run inside an agent session (Kyberion agent runtime, or a provider CLI such as Claude Code) opens requests as `agent:<name>`, so the human's approval of it still passes separation of duties, while an operator approving their own terminal request is refused. With separation of duties on, a terminal without an owner member, or an approval typed inside an agent session, stops with a diagnostic; `pnpm organization member ensure-owner` provisions the owner member. With the setting off nothing new is refused.
- **Revoke an approval before it is used** — `pnpm kyberion approvals --revoke <id> [--reason "..."]` withdraws an approved request that was not yet claimed or applied (by its requester, an approver, or the local owner; audited). Every consumer refuses a revoked approval whatever the separation-of-duties setting, and separation-of-duties refusals now name the revoke command.
- **Service recording reviews go through the approval store** — `service_recording capture` opens a review request (also `service_recording request-review --recording <path>`), `review --approve|--reject` decides it in the store (separation of duties, audit) and records `review.approval_request_id`, and promotion re-checks that approval. A review written before this change promotes only while separation of duties is off.
