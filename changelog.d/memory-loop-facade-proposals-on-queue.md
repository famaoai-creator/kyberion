category: Changed
---

- Background-review patch proposals (`pipeline_proposal`, `skill_patch`, `memory_consolidation`) are now rows on the one memory candidate queue (`kind: process_improvement`, `origin.record_kind: background_review`, decided via `pnpm background-review`), captured with the mission's tenant scope from its state or, for a session review, the session owner's personal scope. A review with neither is not captured (`MEMORY_SCOPE_REQUIRED`). `pnpm background-review request|apply|apply-skill|apply-memory|rollback|pin|hold|manage|restore|curate` act on those rows. A session proposal sits in its owner's partition, so it is found only with its exact `--scope-json`. Archiving marks the row `rejected`, and restoring returns it to `queued`.
- Execution-feedback improvement proposals are also queue rows (`kind: execution_feedback`, `origin.record_kind: execution_feedback`, decided via `pnpm kyberion improvements`), captured with the feedback's scope. Dot memory distillation and dot rejections use the dot charter's own scope. Feedback recorded without a scope is still stored, but its proposal is not captured: the result's `not_captured` field gives the reason, and `pnpm kyberion feedback` prints it. `--queue` hands a proposal to human review as before. The review row now cites the proposal as `artifact:execution_feedback:<id>`, where it used to cite a file path.
- The old distill-candidate files for both flows are now read-only history. For one release, `pnpm background-review migrate [--dry-run]` and `pnpm kyberion improvements --migrate [--write]` import pending items with the scope their record or mission state declares. Background-review imports also include applied patches that have not been rolled back, so a rollback stays possible. Items whose scope cannot be determined are listed under `unresolved` rather than guessed.
- New boundary test `tests/distill-candidate-receipt-boundary.test.ts`: a `DistillCandidateRecord` is written only by the promotion workflow (as a receipt) and by four producers that have not moved yet. That list can only shrink.
