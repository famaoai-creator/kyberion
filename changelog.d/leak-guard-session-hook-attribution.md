- **A strict test run started by an AI agent session no longer fails on the session's own audit rows.** The kyberion-claude-code hooks (PostToolUse, UserPromptSubmit, Stop) append to the live audit chain of the checkout the session works in, including while the session's own `pnpm kyberion pr preflight` or `KYBERION_TEST_LEAK_STRICT=1` Vitest run is in progress. The live-state leak guard reported that growth as a test leak. Hook rows now carry a `metadata.session_hook` provenance stamp (host, event, session id). A hook writes the stamp only for a payload with a host session id, and never from a process that carries a test-run marker (`VITEST`, `VITEST_POOL_ID`, `VITEST_WORKER_ID` or `KYBERION_VITEST_RUN_ID`). The stamp stores the host session id in audit metadata and in the metrics row. The Stop hook's `claude-code-cli` token-usage row in the execution-metrics ledger carries the same stamp, because it lands mid-run when an agent ends its turn during a background run. The guard reads only the appended rows of a file that kept its inode. When every one is a stamped row of a kind the hooks write, the guard lists the file under `session_hook_appends` and does not count it as a leak. Rows from the tenant audit mirror count too, and a lock under `active/shared/runtime/locks/` that is gone by report time is not reported. Each of these still reports the file: one unstamped row (tier-guard denial rows from PreToolUse are unstamped), one stamp on another row kind, an unparseable row, a replaced file, co-session growth, or any other created file. The report's `grown_unattributed` field gives the first unattributed line's number and row kind for each reported file. When a created audit or audit-mirror file holds only stamped rows, the report names it in `created_session_hook_only` as a likely UTC rollover, so rerun the tests. You no longer need to start the run from a different cwd. Hook rows recorded by a runtime built before this change carry no stamp, so rebuild (`pnpm build`) the checkout the plugin's hooks run from.
