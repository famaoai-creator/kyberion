# Same-Checkout Co-Execution Playbook

One page for "several LLM CLIs running in the same directory". Canonical contracts win on conflict:

- [Multi-Provider Co-Execution Contract](../governance/multi-provider-coexecution-contract.md)
- [Agent Communication and Coordination Model](../architecture/agent-communication-layer-model.md)
- [Co-Session Coordination](../architecture/co-session-coordination.md)
- [Workspace Isolation](../architecture/workspace-isolation.md)

## 1. See who is here

1. Obey the startup cwd contract: launch at the repository root, or the mission worktree root when on a mission. Never a subdirectory.
2. Greet with presence before writing:

```bash
pnpm exec tsx scripts/co_session.ts status --session-id <id>
pnpm kyberion workspace list --json
```

`status` shows participants, path leases, and un-acked handoffs. Presence is heartbeat-based (`presence.jsonl`); an expired heartbeat is releasable. `ps` output is not the source of truth (pid reuse) — the workspace ledger's `pid + pidStartedAt` check is.

## 2. Talk once you know you share the checkout

| Situation                                     | Use                                                             |
| --------------------------------------------- | --------------------------------------------------------------- |
| Shared note / goal                            | `co-session blackboard` append / show                           |
| Request to one instance                       | `handoff create --to-participant-id <provider-pid>`             |
| Broadcast to a provider kind                  | `handoff create --to claude`                                    |
| Separate Kyberion runtime (even on localhost) | Peer Messaging + explicit accept, never Co-Session              |
| Git / approval / customer evidence needed     | Promote to mission (`mission_controller`), check `promote-hint` |

Participants are `provider + participant_id` (default `{provider}-{pid}`). One model running twice means two participant ids. `promote-hint` only prints the next command, it never executes.

## 3. Don't collide on writes

- Read: all providers, parallel, unrestricted.
- Write (repo files): the work-item claim holder only. Without a mission, take a short-TTL `lease acquire` first — a cooperative marker, not authorization or enforcement.
- `.git` / repo config: mission owner only, never a worker CLI, never from Co-Session.
- Temp: purpose-fixed floors only (`active/shared/tmp/`, `staging/`, `cache/`, deliverables via `writeScopedArtifact`). No ad hoc dirs.
- Provider state dirs (`.claude/`, `.codex/`, …): never hand-edit; regenerated by ceremony.
- Shared git index: `implementer` delegations get a private `GIT_INDEX_FILE` (WS-01/02), so a stray `git add` never stages into the shared index. A worker commit is absorbed by dispose reconciliation, not by convention.

Order of authority: `path lease (coordination) < work-item claim (write authority) < mission owner (.git)`.

## 4. Special rule: kyberion self-development always uses a worktree

When the origin is kyberion itself and the change touches code:

- Do real work only inside `.worktrees/<sessionId>` created via the owner path `createSessionWorktree` (budget-checked, ledger-registered). No direct writes on `main`.
- Workers never run `worktree add/remove`; removal is `deleteRegisteredWorkspace` → `git worktree remove --force`, with the clean-worktree check. Never `rm` a worktree.
- Knowledge promotion follows the same root (`memory-promote --target-root <worktree>`), so lessons ship in the same PR as the code.

Why: it removes shared-index races, silent HEAD reverts from worker commits, and invisible diffs — one checkout, one writer, reviewable history.

## 5. Operational loop (polling is mandatory, not optional)

Co-Session has no push: presence, blackboard, and handoffs are files you must re-read.
`listCoSessionPresence` drops entries unseen for 5 minutes (`DEFAULT_PRESENCE_STALE_MS`),
so an idle CLI vanishes and a crashed one lingers. Documenting the commands is not enough —
run this loop:

1. On start: `join --as <provider> --note "<what you do here>"`.
2. At least every 5 minutes: `heartbeat --as <provider>`.
3. Before every write: `status` (lease check) + `handoff list --pending-only`.
4. On exit: `leave --as <provider>` to release your leases.

## 6. opencode injection via watcher

opencode sessions accept external messages (`opencode run --session <id> "<message>"`
queues the next turn on the running background service; `opencode api` for programmatic
access; `serve`/`acp` for persistent connections). A same-checkout watcher bridges the two:

- Trigger: new row in `handoffs.jsonl` addressed `--to opencode` (or `--to-participant-id
<opencode-pid>`) with no `acked_at`.
- Action: `opencode run -s <mapped-session-id> "<subject + body>"`, then record delivery in
  a separate cursor file — do NOT `ack` on delivery; the opencode side acks when handled.
- Guards: same checkout only (never a peer/Mesh bridge); skip handoffs already delivered
  (idempotency cursor); never auto-start a mission or approval from a handoff —
  transport receipt is not work acceptance.
