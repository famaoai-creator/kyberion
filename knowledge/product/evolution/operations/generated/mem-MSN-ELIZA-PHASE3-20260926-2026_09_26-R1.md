# Security-sensitive seams: bind, redact, and scope every entry point

Checklist distilled from Phase 3 review blockers across plugin views, private git indexes, visual marks, and video cache.

## Procedure Steps

1. When adding a seam that lets agents reach plugins, screen content, or caches, check each entry point for five things — every one was a review blocker in MSN-ELIZA-PHASE3: (1) Bind loaded content to its approved digest and invalidate the channel on navigation — an iframe self-navigation otherwise keeps the postMessage broker open and bypasses digest approval. (2) A private session git index must refuse to commit when HEAD moved past the seeded baseline, or the owner's commit silently reverts delegate work. (3) Run screen-capture redaction before OCR/VLM output reaches artifacts — unredacted OCR labels leaked into SVG overlays and marks. (4) Scope caches and state by tier and tenant, and classify paths case-insensitively and symlink-safely — never fail open to a lower tier. (5) Represent pending host/agent hand-offs with one marker per target claimed only on matching target+prompt+content change, never by file existence.

## Safety Notes

- Require approval before irreversible or high-risk actions.
- Capture evidence before and after the action.

## Escalation Conditions

- Unexpected runtime failure
- Policy or approval mismatch
- Result does not match the expected state
