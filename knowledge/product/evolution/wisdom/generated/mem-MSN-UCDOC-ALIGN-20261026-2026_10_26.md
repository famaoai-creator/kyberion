# Vertical templates must only use ops resolvable in the actuator op registry

templates/verticals and browser fragments drifted onto non-existent ops (ref+vars, for_each, extract, wisdom:decide_approval, browser:reserve...) and plaintext password fills that leak into action_trail. Fixed all three templates plus intra-login/browser-session-start/ringi-approve-single fragments; added a regression test asserting op resolvability; added the canonical Jira watch template and USE_CASES clarifications.

## Hint Scope

mission

## Trigger Phrases

- Rules learned: (1) bare ops normalize to system:* — fragments intended for core:include must use qualified ops (browser:goto not goto). (2) browser:fill records resolved text into action_trail — credentials must go through fill_secret_ref/fill_ref+secret_ref which auto-redact; fill_secret_ref requires dom_path corroboration. (3) Unresolved {{var}} resolves to empty string — use not_empty, not exists, in core:if conditions. (4) core:foreach takes items/do/as; on_error:skip leaves stale ctx values, so verdicts should carry a key (item_index) verified in the branch condition. (5) Project-local pipelines are trust-gated ([TRUST_REQUIRED]) — document the approval step before any smoke test. (6) Scheduled delivery uses the schedule block + Chronos; pipeline-templates ship enabled:false and writes stay approval-gated.
