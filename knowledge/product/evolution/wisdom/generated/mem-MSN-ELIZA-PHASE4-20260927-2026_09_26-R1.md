# Surface E2E and OS-detector gotchas: bundle layers, readable credentials, frontmost windows

How to E2E a Chronos surface feature and what goes wrong with OS accessibility detectors.

## Hint Scope

mission

## Trigger Phrases

- E2E pattern: run a production Chronos build against a hermetic KYBERION root under active/shared/tmp, install the plugin through the governed install+approval path with a checked-in fixture, and assert on audit/approval stores rather than screenshots. Gotchas found the hard way: (1) Next.js compiles instrumentation.ts in its own webpack layer with a separate copy of every bundled module — a plugin host started there registers ops that route handlers never see; create singletons in the request-serving layer (idempotent boot helper called by the route). (2) Tenant allowlists read from the personal-tier registry must be read under a role that can read it (chronos_localadmin), not the surface's default role. (3) Catalogs must not resolve schema files from cwd — resolve from the governed root. (4) OS accessibility reads must return only the frontmost window's elements — a named-window read leaked a background app's controls; report not_frontmost instead. (5) In a ranked detector seam, a provider failure must fall through to the next provider rather than abort.
