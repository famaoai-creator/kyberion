# Windows portability checks for local speech and governed runtimes

Normalize repository paths and text for semantic validation, keep native process and file boundaries portable, and disclose platform fixture limits before publishing.

## Hint Scope

mission

## Trigger Phrases

- When bringing an existing runtime to Windows, reproduce each boundary independently: portable logical lock filenames, narrow executable-discovery environment, UTF-8 Python streams, governed local speech discovery, workspace web launchers and native archive moves. Explicit user-configured speech bridges should outrank automatic discovery; error and empty responses must not persist successful transcripts.

Repository validation must compare normalized relative paths and CRLF/LF text semantics while preserving authored line endings on actual edits. Do not raise baselines to mask Windows false positives. Node --import arguments for absolute loader paths must be file URLs. A Next.js dependency launcher should resolve authority analysis to its declared workspace app sources, not dependency code.

Use an independently installed worktree, full build, required readiness gates and focused regressions. Report Unix fixture and Windows symlink-permission failures separately from successful production tests. Restart lock users during filename-mapping upgrades to avoid mixed-version mutex names; native archive moves require same-filesystem placement. Passing local checks is not evidence of PR publication or hosted CI success.
