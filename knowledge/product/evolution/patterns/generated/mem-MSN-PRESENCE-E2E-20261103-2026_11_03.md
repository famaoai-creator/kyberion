Gitignored per-checkout stores (charters, approvals) made a grant issued from concierge invisible to linked worktrees, so every worktree action re-requested human approval; separately, member-API allowlist drift produced silent TypeErrors in the UI.

## Expected Outcome

Rule: state that is logically one-per-repository (authority charters, approval stores) must resolve to the primary checkout, not the linked worktree — detect worktrees via the .git file + commondir, remap only declared authority prefixes, and teach every boundary layer (relative-path spelling, canonicalization, inode/TOCTOU checks, mkdir, tier guard) the restricted second root. Keep project-root-first resolution so fixtures stubbing rootDir() still work. Separately: any client allowlist over API paths needs a static sweep test (callsite -> allowlist + route existence, with dynamic-segment normalization) or it silently drifts — route groups and [id] dirs make naive path matching produce false positives. UI-integration footgun: window.open('', '_blank', 'noopener') always returns null, losing the popup handle needed for OAuth consent flows.
