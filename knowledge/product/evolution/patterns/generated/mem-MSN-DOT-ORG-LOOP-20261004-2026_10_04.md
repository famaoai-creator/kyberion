## Expected Outcome

Lessons from closing the resident-dot organization loop (DL-01..11):

1. Every claimed unit of autonomous work needs a terminal path. Dispatch counted `blocked` and `in_progress` WorkItems as open delegations, so escalations, crashed claims and hung pipelines held a dot's slots forever. An executor must (a) bound each item by wall clock with abort, (b) reap stranded claims before each sweep, and (c) release escalations to a terminal status, keeping the real status in metadata.
2. A long-lived daemon must bootstrap reasoning itself (`installReasoningBackends()` + periodic reselect). Otherwise `getReasoningBackend()` is the stub, and a stub delegate silently records fake deliveries. Refuse the unconfigured stub explicitly.
3. Keep an extension registry a leaf (arrays only) and register extensions from a bootstrap module imported by entry points. Registries that import their extensions form runtime import cycles with the modules that read them (dep-cycles / module-boundaries gates).
4. Model-proposed advisory metadata (expected_effect, target, intent) must be dropped when malformed, not used to reject the proposal: a live wake invented a target form and lost valid work.
5. Tenant-bound reads must bind the file to its directory's tenant AND run inside that tenant's execution context. Listing in context but reading in the caller's context fails tier-guard in the daemon.
6. Tests of feedback, distill or budget code must inject ports. Defaults that write `active/shared/runtime/execution-feedback.json` or read real metrics history pollute other suites (the full run failed on execution-feedback.test.ts).
7. Since #909 the repository path boundary rejects relative roots. Resolve a registry `rootDir` with `path.resolve` before calling tenant-registry helpers.
8. Per-wave independent review paid off: 15 blocking findings across 3 waves (tenant escapes, slot leaks, races), all caught before the PR.
