# Unified work views preserve source authority and read-only evidence

A work dashboard is a projection of existing work, not a new execution or approval engine. Preserve the strictest source-specific access boundary when combining sources. A remote-safe aggregate must not expose a localadmin-only conversation. Validate tenant, organization, project and tier claims before titles, associations or links; conflicting legacy claims fail closed.

Read-only is a behavioral property, not an HTTP verb. Existing readers may publish synchronized reports, reconcile approvals or refresh observation journals. Use explicit pure projections for Home and Resume, and verify that those paths do not write, decide, apply or replay work.

Keep conversation answers separate from executed results. Pending amendments override retained answers. Only current matched execution and byte/hash evidence justify verified completion; record time and checked-at time are distinct. An unverified new revision never replaces the latest verified parent.

Incomplete source windows and failed readers are not empty queues. Report partial or unavailable coverage, including capped windows that contain no pending rows. Do not silently broaden a selected scope when an existing decision screen cannot preserve it; retain the item with an unavailable-destination explanation.

Quiet display can reduce detail while retaining decisions, uncertainty and version currentness. Store only the display enum under a server-scoped fingerprint. Navigation remains inert; historical focus is one-shot after hydration. Keep source/DOM checks, actual browser validation, aggregate gates and environment-limited tests distinct in delivery evidence.
