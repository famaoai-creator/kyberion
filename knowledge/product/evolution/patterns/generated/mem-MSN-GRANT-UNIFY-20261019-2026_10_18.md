# macOS capture permissions: probe without prompting, request only via explicit warm-up from a terminal host

TCC grants (microphone, camera, screen recording) belong to the responsible host app, not to the helper binary. Probe them with authorizationStatus/CGPreflight (never prompts) and ask macOS ahead of time only through `pnpm kyberion permissions warmup`, run from a terminal host.

## Expected Outcome

- Grants are attributed to the responsible process (Terminal / iTerm / IDE for CLI helpers; Chrome or Playwright Chromium for browser capture). Switching terminal apps means a fresh first-time prompt, so report `host_app` alongside every probe result.
- Keep probing and requesting in separate Swift sources: `macos-native-automation.swift` must never call requestAccess / CGRequestScreenCaptureAccess (source test enforces it); prompting lives only in `macos-permission-warmup.swift`.
- `AVAuthorizationStatus.restricted` (MDM / Screen Time) is not fixable in System Settings: surface it as `restricted` with an administrator remedy, not as `denied`.
- CGPreflightScreenCaptureAccess is boolean, so undetermined and denied are indistinguishable: report `unknown`, and always point at the Screen Recording settings pane (it also needs a host-app restart).
- requestAccess from a process without a usage description (daemon, launchd) can abort it: refuse warm-up when no terminal host app is identified, and run one helper process per kind so a failure keeps the other results.
- Never trust an env self-report (`KYBERION_AUDIO_PERMISSION_CONFIRMED`) when the real state is probeable; keep it only as a fallback.
