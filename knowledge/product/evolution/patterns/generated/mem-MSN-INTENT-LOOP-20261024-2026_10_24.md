# Response parsers are a distinct seam when adding view data

When a backend view gains fields for a UI, the response parser must be extended and tested too — builder+component tests alone let shipped UI go dead-code.

## Applicability

- mission
- mission:MSN-INTENT-LOOP-20261024

## Reusable Steps

1. When a backend view gains fields for a UI, the response parser must be extended and tested too — builder+component tests alone let shipped UI go dead-code

## Expected Outcome

When extending a management/control-plane view with new fields for a surface, treat the response parser (e.g. chronos organization-operating-model-response.ts) as a third implementation site: extend it and add a parse-level test asserting the fields survive. An independent review caught the new objective roll-up fields being stripped at exactly this boundary.
