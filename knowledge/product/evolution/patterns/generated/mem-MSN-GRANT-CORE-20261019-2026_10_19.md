# Standing grants must be bound to their consumed approval and re-verified on every use

A standing (reusable) permission backed by a one-shot human approval is only as strong as the binding between the stored grant record and that approval. Verify the binding at use time, not only at grant time.

## Applicability

- mission
- mission:MSN-GRANT-CORE-20261019

## Reusable Steps

1. A standing (reusable) permission backed by a one-shot human approval is only as strong as the binding between the stored grant record and that approval
2. Verify the binding at use time, not only at grant time

## Expected Outcome

- Record what the approval created: put the effect id (grant id) into the approval's consumption (`effectRef`) and use the consumption time as the grant's start time; re-check both exactly on every use.
- Re-derive the approval payloadHash from the stored record (capability, tenant, scope, purpose, whole-day lifetime — no rounding) so widened scope or shifted windows grant nothing.
- One approval backs exactly one record: if several records name the same approval, none of them grants (blocks copy-to-new-id).
- Revoking a standing effect must also withdraw its approval (`revokeStandingEffectApproval`, only when consumer + effectRef match), otherwise editing `revoked` out of the record resurrects it. Withdraw first, then audit the outcome.
- Attribute revocations truthfully: check for an agent principal before falling back to the terminal owner, and carry the actor kind into the audit.
- Inside a mission, take the tenant from the mission state, never from the caller or ambient identity, before matching tenant-scoped grants.
- These gaps were found only by an adversarial independent review; schedule one for any new grant/consent store.
