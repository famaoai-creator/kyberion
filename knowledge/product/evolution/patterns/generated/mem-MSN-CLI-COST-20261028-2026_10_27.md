# Treat missing CLI billing evidence as unknown, and keep reference prices separate

Normalize provider transport usage into the existing ledger while distinguishing actual, estimated, included and unknown cost without cache, event or parent-child double counting.

## Applicability

## Reusable Steps

1. Normalize provider transport usage into the existing ledger while distinguishing actual, estimated, included and unknown cost without cache, event or parent-child double counting

## Expected Outcome

For CLI accounting, trust structured transport envelopes rather than model-generated response text. Separate usage provenance, cost provenance, billing mode and resource lifecycle. Parse provider cache buckets and final cumulative events before aggregation so cached input, interim events and parent-child summaries are not billed twice. A successful unmetered response may retain a clearly labeled character estimate; a definitely unsent invocation must not be charged from prompt length. Do not infer subscription coverage from the executable name or login state. Provider-reported API-equivalent amounts remain reference prices when incremental billing is unproven, and reference prices must not be added to additional spend. Retain unknown-cost calls in coverage counts and show a known subtotal; invalidate a confirmed remaining-budget claim when coverage is incomplete. Keep tenant/accounting attribution and existing settlement boundaries. Offline counter and scope fixtures establish normalization behavior, not agreement with live invoices; resumed-session cumulative deltas require their own contract.
