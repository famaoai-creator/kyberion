### Changed

- **Codex GPT-6 models and cost attribution** — register GPT-6 Astra, Sol, and
  Luna; use GPT-6 Sol as the Codex default and GPT-6 Luna for fast-tier work.
  Add current token and cache rates to the model cost registry. GPT-5.6 rates

### Fixed

- **`computer_interaction` ref remint** — browser lowering no longer inserts a
  fresh `snapshot` before `click_ref` / `fill_ref` / `press_ref` /
  `wait_for_ref` / `extract_text_ref`. A reminted `@e1` is not the
  observation-time field; same-session `keep_alive` reuses the last
  snapshot's `ref_map`. Durable `selector` / `name` / `role` / `dom_path`
  are now first-class on the contract and preferred over ephemeral `@eN`.
  `fill_secret_ref` (and `fill_ref` + `secret_ref`) require a corroborating
  `selector` or `dom_path` and fail closed instead of snapshot+`@eN`.
  `requireDomPathMatch` still corroborates a `ref_map` hit so a remapped
  `@e1` cannot receive a secret.

### Added

- **Shell scripts go through dedicated helpers** — `safeExec` /
  `safeExecResult` / `safeExecResultAsync` / `safeSpawn` now reject a
  `sh|bash|cmd` + `-c|-lc|/c` invocation; use `safeExecShellScript` /
  `safeExecShellScriptResult` (or the `system:shell` op in pipelines). A
  hand-written pipeline that runs `system:exec` with `command: "bash"` and
  `args: ["-c", ...]` now fails with a `[SECURITY]` error — switch it to
  `system:shell`. This removes the CodeQL
  `js/shell-command-constructed-from-input` false positives (698 → 8
  locally). Read-only members can now manage their own recording consent in
  Concierge Settings › Recording.

- **Work inventory follow-ups** — test runs no longer write production traces
  (opt back in with `KYBERION_TRACE_TEST_PERSIST=1`) and traces carry
  `metadata.origin`; the harvest drops test/ci traces. Members manage their own
  PC-recording consent and review their summaries in Concierge Settings ›
  Recording. The storage janitor expires unconfirmed/discarded observation
  summaries via catalog `status_rules`. `safeExec`/`safeExecResult` pass
  `shell: false` explicitly and reject a `shell` option. `pnpm inventory
migrate` tags legacy taxonomy-default bindings.

- **Work inventory (業務棚卸し) discovery stage** — decompose recurring PC work
  into steps (7 stages x 12 verbs) and classify each step as api /
  computer_operation / ai_reasoning / program / human by catalog rules
  (models only propose). Real data comes from the hearing
  (`/ask?mode=hearing&scenario=work_inventory`), Kyberion usage logs, and
  consented PC-operation recordings (member-owned consent, allowlist
  summaries only). Candidates are ranked, promoted by a human, measured
  after promotion and fed back into calibration. CLI: `pnpm inventory`.

- **Agent pane runtime + tool lifecycle** — optional `pane` launch mode via
  `agent-pane-runtime-bridge` (Herdr provider), with governed install through
  tool-runtime entries `herdr` / `imagesnap` / `blackhole-2ch` and
  `pnpm tool:setup -- --tool herdr [--apply]`. Neighboring seams

### Fixed

- **`browser:export_adf` replay** — `renderBrowserAdf` now prefers recorded
  `selector` / role / name and emits canonical `click` / `fill` / `press` /
  `wait` instead of deprecated `click_ref({ref:'@eN'})`. Fresh-session replay
  no longer depends on a keep_alive snapshot's ephemeral ref_map. Ref-only
  trails insert a `snapshot` before the apply step. Secret fills persist a
  corroborating `dom_path` (explicit trail field, else recorded selector) so

  Ref-only secret fills are omitted from export (fail closed). A ref_map hit
  with `requireDomPathMatch` is used only when it is the same live element
  as the recorded `dom_path`.

### Security / migration notes

- **`KYBERION_ALLOW_UNAUTH_REMOTE` now parses the full boolean vocabulary.** Chronos Mirror's API guard (`presence/displays/chronos-mirror-v2/src/lib/api-guard.ts`) reads this flag through the registered env accessor, which accepts `1`, `true`, `yes` and `on` (case-insensitive); it previously matched only the literal string `true`. **Affected**: any deployment that set the flag to a truthy value other than `true` — it used to be a silent no-op that failed closed, and it now genuinely enables unauthenticated remote readonly access — but only when neither `KYBERION_API_TOKEN` nor `KYBERION_LOCALADMIN_TOKEN` is configured; token-configured deployments are unaffected. **Action**: audit the value of `KYBERION_ALLOW_UNAUTH_REMOTE` in every environment and unset it (or set it to `false`) unless unauthenticated remote reads are intended.
- **Forwarded client-IP headers are no longer trusted by default (`KYBERION_TRUST_PROXY`).** Chronos Mirror and Concierge (`presence/displays/concierge/src/lib/viewer-context.ts`) ignore `x-forwarded-for` / `x-real-ip` when determining whether a request is loopback, unless the new `KYBERION_TRUST_PROXY` flag is enabled (default off). This closes a header-spoofing path to local-admin privileges. **Affected**: local deployments served through a reverse proxy, which were previously treated as loopback and may now require a token. **Action**: set `KYBERION_TRUST_PROXY=1` only when a trusted reverse proxy overwrites those headers on every inbound request; otherwise leave it unset and issue a surface token instead.

- **Surface viewers never receive the `personal` tier.** Chronos Mirror and Concierge now resolve a registered `localadmin` token that omits `tier_access` to the masked role default (`confidential`, `public`) instead of rejecting it (Chronos previously returned 403 for such registrations), and reject a registration that explicitly requests `personal` with 403. **Affected**: hand-written token registrations that list `personal` in `tier_access`. **Action**: remove `personal` from `tier_access`; personal-tier access is only available to local sovereign processes.
- **Loopback auto-admin requires a trusted proxy on Next.js 15+.** `NextRequest.ip` no longer exists, so without `KYBERION_TRUST_PROXY=1` (behind a proxy that sets `x-real-ip`/`x-forwarded-for`) a browser on the same machine is not detected as loopback and must present a surface token even when `KYBERION_LOCALHOST_AUTOADMIN` is enabled.

## How releases are tagged

We use Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `breaking:`).

- `feat:` and `feat(scope):` → minor bump (or major if `BREAKING CHANGE:` footer)
- `fix:` → patch bump
- `breaking:` or `BREAKING CHANGE:` footer → major bump
- everything else → no bump (rolled into the next minor/patch)

When a release is tagged, `scripts/generate_changelog.ts` populates a new section above with the commits since the previous tag.
