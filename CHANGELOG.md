## [Unreleased]

### Added

- **APQC business workflow catalog and intent registration** — the mission
  workflow catalog now covers all APQC PCF level-1 categories (72 templates,
  v1.5.0), translating human business processes such as invoice processing,
  payroll, business planning, product roadmaps, due diligence, RFP responses,
  internal audit, BCP, and release change management into governed mission
  phases with review gates and approvals. Intent-keyed templates now sit ahead
  of generic catch-all templates so dedicated workflows are actually selected
  (template matching is first-match). Thirty representative workflows are
  registered in `standard-intents.json` (168 intents, v2.2.0) and
  `intent-domain-ontology.json` (v1.2.0), so natural-language requests resolve
  end to end into missions backed by the dedicated workflow templates.
- **Creative assembly loop for media/document workflows** — mission workflow
  templates for presentation decks, documents, and video now follow a
  scratch-first / pipeline-second lifecycle: semantic briefs and scene/spec
  planning (judgment) feed agentic scratch rendering, the assembled artifact
  itself is evaluated with per-slide/per-scene/per-section flags, only flagged
  parts are repaired, and the accepted recipe is frozen into a design protocol
  or promoted to a governed pipeline only when reuse is expected. A new
  `video-production` template covers goal → spec → scene plan → asset
  generation → assembly → artifact evaluation → repair → promotion → publish →
  learn. Conditional `when` clauses on phase task specs let workflows attach
  tasks only for matching mission classes, intents, task types, or keywords —
  `code-change-aidlc` now adds a conditional `experience_designer` UX contract
  task for UI/UX-impact missions, and the `development` team template lists
  `experience_designer` as an optional role.
- **Curated mission knowledge promotion** — distillation remains archived as
  mission evidence; stewards now shape a reusable title, summary, content, and
  evidence set before approval, then promote it into the selected product,
  organization, or personal knowledge domain. Mission completion no longer
  creates a duplicate generic memory candidate. Code-change testing is assigned
  to the tester role, and retrospectives record knowledge and team/process
  improvement dispositions.
- **Authn/authz seams wired across surfaces** — Concierge, Presence Studio,
  Chronos Mirror, headless, and local surfaces now resolve a verified
  principal through `authn-principal-resolver`, project it with
  `toSurfaceViewerScope`, and evaluate authorization through
  `authz-policy-engine`. Adapter-owned transport facts (loopback proof,
  request headers, server-side tenant binding, pre-fetched JWKS) stay in
  the adapters; client-supplied tenant/tier values may only narrow an
  already-authorized scope.
- **External IdP → member mapping** — member profiles can bind OIDC
  `external_identities` (`issuer` + `subject`, e.g. Google accounts). The
  `oidc-jwt` provider resolves `member_id` claims, `user:<member_id>`
  subjects, and external identity lookups to the member's own
  memberships. Bound-but-suspended or unverifiable bindings are denied
  (`403 scope_denied`) at authentication and at every member-aware gate;
  registry corruption fails closed instead of degrading to the
  unregistered path.
- **Human membership roles** — `owner`, `approver`, `operator`, and
  `viewer` member roles map onto `localadmin`/`readonly` server roles
  with exact permissions (approver decides without generic writes,
  operator executes without deciding). Decision routes attribute to the
  resolved member on the resource tenant. See
  `knowledge/product/architecture/external-identity-member-mapping.md`.

### Fixed

- **Cognitive routing metadata feedback loop** — dispatch write-back metadata
  (`last_*`, `drift_watchdog_*`, `security_scope`, `summary`, execution
  bookkeeping) no longer feeds route scoring, and generated identifiers
  (`prefix-<8 hex>`, UUID fragments) are stripped from the scoring text so a
  random hex id can no longer trip the `adf` marker. Previously a single run
  could flip a work item to `zero_llm`/`deterministic_pipeline` and pin it
  there permanently via `last_cognitive_route_summary`, and the drift watchdog
  signature — which embeds the route summary — could change on every retry so
  identical outcomes were never detected as repeats.
- **Chronos Mirror latent type errors** — ~240 errors outside the root
  tsconfig scope are repaired (non-strict narrowing on discriminated
  unions, untyped request bodies, missing imports after file splits,
  `SupportedLocale` drift); the app now typechecks clean. The
  `presence/bridge/terminal`, `plugins`, and `skill-template-ts`
  tsconfigs no longer resolve `@agent/core` into sources — they consume
  `dist`, removing hundreds of transitive strict-mode errors.
- **`computer_interaction` ref remint** — browser lowering no longer inserts a
  fresh `snapshot` before `click_ref` / `fill_ref` / `press_ref` /
  `wait_for_ref` / `extract_text_ref`. A reminted `@e1` is not the
  observation-time field; same-session `keep_alive` reuses the last
  snapshot's `ref_map`. Durable `selector` / `name` / `role` / `dom_path`
  are now first-class on the contract and preferred over ephemeral `@eN`.
  `fill_secret_ref` (and `fill_ref` + `secret_ref`) require a corroborating
  `selector` or `dom_path` and fail closed instead of snapshot+`@eN`.
  `requireDomPathMatch` still corroborates a `ref_map` hit so a remapped
  `@e1` cannot receive a secret.

### Added

- **Shell scripts go through dedicated helpers** — `safeExec` /
  `safeExecResult` / `safeExecResultAsync` / `safeSpawn` now reject a
  `sh|bash|cmd` + `-c|-lc|/c` invocation; use `safeExecShellScript` /
  `safeExecShellScriptResult` (or the `system:shell` op in pipelines). A
  hand-written pipeline that runs `system:exec` with `command: "bash"` and
  `args: ["-c", ...]` now fails with a `[SECURITY]` error — switch it to
  `system:shell`. This removes the CodeQL
  `js/shell-command-constructed-from-input` false positives (698 → 8
  locally). Read-only members can now manage their own recording consent in
  Concierge Settings › Recording.

- **Work inventory follow-ups** — test runs no longer write production traces
  (opt back in with `KYBERION_TRACE_TEST_PERSIST=1`) and traces carry
  `metadata.origin`; the harvest drops test/ci traces. Members manage their own
  PC-recording consent and review their summaries in Concierge Settings ›
  Recording. The storage janitor expires unconfirmed/discarded observation
  summaries via catalog `status_rules`. `safeExec`/`safeExecResult` pass
  `shell: false` explicitly and reject a `shell` option. `pnpm inventory
migrate` tags legacy taxonomy-default bindings.

- **Work inventory (業務棚卸し) discovery stage** — decompose recurring PC work
  into steps (7 stages x 12 verbs) and classify each step as api /
  computer_operation / ai_reasoning / program / human by catalog rules
  (models only propose). Real data comes from the hearing
  (`/ask?mode=hearing&scenario=work_inventory`), Kyberion usage logs, and
  consented PC-operation recordings (member-owned consent, allowlist
  summaries only). Candidates are ranked, promoted by a human, measured
  after promotion and fed back into calibration. CLI: `pnpm inventory`.

- **Agent pane runtime + tool lifecycle** — optional `pane` launch mode via
  `agent-pane-runtime-bridge` (Herdr provider), with governed install through
  tool-runtime entries `herdr` / `imagesnap` / `blackhole-2ch` and
  `pnpm tool:setup -- --tool herdr [--apply]`. Neighboring seams
  (`agent-exec-adapter`, `audio-bus`, OCR/image-gen/calendar/browser) keep
  vendor names out of callers.
- **Local music CLI backends** — `music-generation-bridge` adds MusicGen/MLX
  (`musicgen_mlx`) and Stable Audio 3 Small-Music (`stable_audio_3`) as
  ComfyUI alternatives, registered via tool-runtime / media-backend /
  `KYBERION_MUSICGEN_*` + `KYBERION_STABLE_AUDIO_*` env policy. Direct prompt
  examples land in media-generation-actuator.
- **Cursor host image bridge** — `image-generation-bridge` can route through
  the Cursor host CLI when available (`cursor_host_bridge`).
- **Gemini API key recovery** — `KYBERION_GEMINI_API_KEY` is the governed
  secret for gemini-api reasoning, Imagen, Veo, embeddings, OCR, and the AGY
  SDK bridge; `GEMINI_API_KEY` / `GOOGLE_API_KEY` remain compatibility aliases.

- **Playwright browser execution host** (`pnpm kyberion browser run`) wires
  `execution_substrate: 'playwright'` through `dispatchProcedure` into
  `@agent/browser-actuator` `handleAction` without a core→actuator import.
  Catalog procedures, allowlisted approved recordings, and hand-authored ADF
  examples share the same helper; `pnpm kyberion procedure run` no longer
  requires `--tab-id` for standalone Chromium. `--tab-id` remains an optional
  session label and does not enable CDP attach by itself; attach only with
  `--cdp-url` / `--cdp-port`. Host-owned runtime flags (`connect_over_cdp`,
  CDP endpoint, `headless`, recording) cannot be overridden by dispatcher
  options. Governance (approval gate +
  origin allowlist) matches the extension path.

### Security / migration notes

- **`KYBERION_ALLOW_UNAUTH_REMOTE` now parses the full boolean vocabulary.** Chronos Mirror's API guard (`presence/displays/chronos-mirror-v2/src/lib/api-guard.ts`) reads this flag through the registered env accessor, which accepts `1`, `true`, `yes` and `on` (case-insensitive); it previously matched only the literal string `true`. **Affected**: any deployment that set the flag to a truthy value other than `true` — it used to be a silent no-op that failed closed, and it now genuinely enables unauthenticated remote readonly access — but only when neither `KYBERION_API_TOKEN` nor `KYBERION_LOCALADMIN_TOKEN` is configured; token-configured deployments are unaffected. **Action**: audit the value of `KYBERION_ALLOW_UNAUTH_REMOTE` in every environment and unset it (or set it to `false`) unless unauthenticated remote reads are intended.
- **Forwarded client-IP headers are no longer trusted by default (`KYBERION_TRUST_PROXY`).** Chronos Mirror and Concierge (`presence/displays/concierge/src/lib/viewer-context.ts`) ignore `x-forwarded-for` / `x-real-ip` when determining whether a request is loopback, unless the new `KYBERION_TRUST_PROXY` flag is enabled (default off). This closes a header-spoofing path to local-admin privileges. **Affected**: local deployments served through a reverse proxy, which were previously treated as loopback and may now require a token. **Action**: set `KYBERION_TRUST_PROXY=1` only when a trusted reverse proxy overwrites those headers on every inbound request; otherwise leave it unset and issue a surface token instead.

- **Surface viewers never receive the `personal` tier.** Chronos Mirror and Concierge now resolve a registered `localadmin` token that omits `tier_access` to the masked role default (`confidential`, `public`) instead of rejecting it (Chronos previously returned 403 for such registrations), and reject a registration that explicitly requests `personal` with 403. **Affected**: hand-written token registrations that list `personal` in `tier_access`. **Action**: remove `personal` from `tier_access`; personal-tier access is only available to local sovereign processes.
- **Loopback auto-admin requires a trusted proxy on Next.js 15+.** `NextRequest.ip` no longer exists, so without `KYBERION_TRUST_PROXY=1` (behind a proxy that sets `x-real-ip`/`x-forwarded-for`) a browser on the same machine is not detected as loopback and must present a surface token even when `KYBERION_LOCALHOST_AUTOADMIN` is enabled.

## How releases are tagged

We use Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `breaking:`).

- `feat:` and `feat(scope):` → minor bump (or major if `BREAKING CHANGE:` footer)
- `fix:` → patch bump
- `breaking:` or `BREAKING CHANGE:` footer → major bump
- everything else → no bump (rolled into the next minor/patch)

When a release is tagged, `scripts/generate_changelog.ts` populates a new section above with the commits since the previous tag.
